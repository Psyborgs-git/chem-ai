## 实现内容

### 1. 不可变绑定的实验计划 `§14.1`

- 新模型 `ExperimentPlan`（迁移 `0017_experiment_plans`）：
  `task_id`（复合 FK）、`title`、`status`
  (`draft|submitted|approved|rejected`)、`payload`（JSONB — 绑定
  candidate/contract/process 修订 id、method、samplePlan、
  acceptanceCriteria、hazardNotes、resourceNeeds）、
  `bound_inputs`、`content_digest`、`blockers`、`approval_id`
  （复合 FK→approvals）、`packet`、`created_by`。
- `studio/domain/lab/plans.py` — `LabPlanService`：
  - `create`/`update`（`CAP_EDIT_TASK`，status∈draft/submitted/
    approved 可编辑）：每次写入重算 `content_digest`（
    `request_digest(payload)`）与 `bound_inputs`，清空已导出
    packet，重新计算 blockers。
  - `submit`：draft→submitted，发布 `experiment_plan.submitted`。
  - `review`：仅持 `CAP_APPROVE_EXPERIMENT`（human 角色 — agent
    kind 在 `effective_grants` 天花板下永远拿不到）可决定；
    批准前若存在未决 blockers → `CONFLICT` + `safe_details.blockers`
    （AT-0501-2）；批准经 `application.approvals.grant` 以
    `action="experiment_release"` 绑定 `{planId, taskId,
    contentDigest}` 的精确 digest。
  - `export_packet`：`CAP_READ_PROJECT` + status=approved +
    `_verify_release_approval` 在导出时重新校验 — 决定、撤销、
    过期（`APPROVAL_EXPIRED`）、digest 失配（`APPROVAL_STALE`）
    全部阻断（AT-0501-1）。packet 含 `executionMode:"manual"`、
    `MANUAL_EXECUTION_LABEL`、精确 revisions、approval 溯源、
    `contentDigest`；**无任何设备执行能力**。
  - blockers 计算：任务未决 mode inputs（`unresolved_inputs`）、
    缺 method、配料缺 `materialId` 或引用未知 MaterialIdentity —
    全部列明，绝不虚构（§21.5）。
- 审计：`experiment_plan.created` / `.packet_exported`；outbox 发布
  `experiment_plan.updated|.submitted|.reviewed`。

### 2. GraphQL

- `ExperimentPlan` Node 类型 + `taskPlans` keyset 连接。
- `lab` 命名空间：`planCreate`（幂等）、`planUpdate`、`planSubmit`、
  `planReview`、`packetExport` — 全部走 `_mutate` + DomainError
  payload 惯例。

### 3. 前端 `apps/studio-web/src/features/lab/plans/`

- `LabPage`：project→task 两级选择器 → `PlansPanel`。
- `PlansPanel`：计划卡片显示 status 徽章、content digest、绑定的
  candidate/contract/process 修订 id、method、blocker 列表；
  按状态出现动作 — draft→submit for review、submitted→rationale+
  approve/reject、approved→export manual packet；packet 区显示
  "MANUAL EXECUTION — qualified operator required" 警告徽章、
  approval id、executionMode 与完整 JSON；页面上不存在任何
  equipment execution 控件。
- 路由 `/lab` 挂载到既有 AppShell 导航。

### 4. 流活性修复（AT-0406-1 回归修复）

e2e 暴露：服务端心跳是 SSE **注释帧**（`: heartbeat`），对
EventSource 不可见；`context.setOffline` 只阻断新建请求，已建立
连接在 Chromium 下保持半开、`error` 不一定触发 — "reconnecting…"
徽章偶发不可见。修复：

- 服务端改发具名 `event: heartbeat` 帧（无 `id:` 字段，不影响
  Last-Event-ID 续传游标）。
- `openStream()` 增加活性看门狗：任一帧（含 heartbeat）刷新
  `lastFrameAt`，>2.5s 无帧即 `onError` → UI 显示重连态；
  `close()` 清理定时器。
- `_MAX_SECONDS` 改为 env 可调（`STUDIO_EVENT_MAX_SECONDS`，
  默认 55），e2e `serve.sh` 设 2s — 每个用例真实经历多次
  close→reconnect→resume 循环，断连不再是时序运气。

## 已知限制 / 能力声明

- **U04 未决**：评审人身份/角色指派未定 — 已实现能力制审批
  （`approve_experiment` capability，agent 被 `effective_grants`
  天花板排除），不虚构评审主体。
- **U05 未决**：实验设备与可用方法未知 — plan 的 `method` 为显式
  需求文本；缺失即为 blocker，不与任何设备目录匹配；系统**无**
  设备执行端点。
- packet 为 JSON 文档（含 MANUAL 标签与 approval 溯源）；PDF/打印
  导出、实验记录回填（operator 录入实际物料批号/样品 id/偏差）
  属 CS-0502 范围。
- `payload` 中的 `contractRevisionId`/`processRevisionId` 作为绑定
  引用记入 digest；存在性校验目前仅覆盖 `candidateRevisionId`
  （配料阻断所需）— 更全面的引用完整性可在后续收紧。
- 软件验收 ≠ 科学验证：fixture 计划证明不可变绑定/审批过期语义，
  不构成对任何真实配方/方法的认可。
