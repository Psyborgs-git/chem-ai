## 实现内容

### 1. `domain/runs/feasibility.py` — 可行性评估 + 决策 + 惰性提案（~850 行）

- **有界 spec**：`parse_job_spec` 把 `run.request`（≤4 KiB canonical
  JSON）解析为 `JobSpec`——operation、≤16 个尺寸维度（sizes）、
  envelope 上界估计（`cpu_cores/memory_bytes/gpu_devices/
  storage_bytes/wall_seconds`，值域 ≤2^63−1）、≤8 个候选配置
  （`ALTERNATIVE_KINDS`：batch_reduction/accumulation/precision/
  offload/other）。所有输入有界，非法即拒。
- **兼容性检查**：`_check_group` 对每个候选配置 × 资源组做保守
  上限判定（`est.high` 对 `capacity − reserve`）——
  `fits`（上界可容纳）/`busy`（可容纳但被预留占用，属暂时性，
  **绝不计为 infeasible**——"更忙 ≠ 不可能"）/`infeasible`
  （上界超出物理容量）；未观测维度记 `missing`，绝不假设充足。
- **候选排除**：`quality_impact=material_needs_approval` 的配置即使
  能装下也不计为可行——实质质量变更需人工批准（§20.1）。
- **决策映射**：`decision_for` 只按 verdict 映射——
  `local_feasible` 或 `export_proposed`；**无云偏好输入**，"云更快"
  在结构上不可能授权云（`cloud_authorized` 恒 `False`）。
- **硬件报告**：`HardwareReport.detect()`（CS-0402）快照入档——
  OS/arch/RAM/GPU/磁盘/运行时/引擎安装/隔离特性 + 时间戳，
  全部可观测事实，无编造吞吐。
- **服务**：`FeasibilityService`——`_lock_run`（FOR UPDATE）→
  `_evaluate_locked`（持久化 `RunFeasibilityReport` + 审计
  `run.feasibility_evaluated`）；`request_fallback`：feasible →
  审计 `run.fallback_local_feasible` 直接返回；infeasible →
  `_propose_export`（**纯决策行**：无 payload/recipient/spend）
  + `RunService.block`（`requested/awaiting_approval → blocked`，
  reason=`local_infeasible`）+ 审计 `run.export_review_proposed`。
  已 blocked 的 run 重评估不会重复 block。
- **提案去重**：`bound_inputs={runId, requestDigest, operation,
  verdict, proposalVersion}` → `bound_digest`；同 digest 复用
  未关闭提案，新报告更新链接而非产生重复提案。
- **能力面**：`cloud_capability()` 恒返回 `not_configured`
  （provider/account/budget=None，egress=deny）——云凭据存在
  也不等于批准（§20.2）；`fallback_view` 内 `require(
  CAP_REQUEST_COMPUTE)` 服务端检查永远生效。

### 2. Persistence + GraphQL

- `models.py` + `migrations/versions/0026_feasibility_fallback.py`：
  `run_feasibility_reports`（run_id/evaluated_by/operation/basis/
  sizes/envelope/configurations/uncertainty/reasons/missing/
  hardware/verdict）+ `export_proposals`（run_id/
  feasibility_report_id/proposed_by/status=proposed/bound_inputs/
  bound_digest/required_capability）——均为审计/决策行，提案
  `status` 域只有 proposed/approved/rejected/withdrawn，
  **无 submitted/executed** 终态。
- `schema.py`：`runs.requestFallback(input)` mutation →
  `FallbackResult{run,decision,cloudAuthorized,report,proposal,
  cloud,errors}`；`runFallback(runId)` query → `fallback_view`。
  schema.graphql 经 `export_schema.py` 导出同步。

### 3. `apps/studio-web/src/features/compute/fallback/` — 决策面 UI

- `operations.ts`：`fallbackRunViewQuery` + `fallbackRequestMutation`
  （Relay 编译产物未手写）。
- `FallbackPanel.tsx`（路由 `/compute/fallback/:runId`）：
  `CloudCard`（恒 `not_configured`/egress=deny）、`ProposalCard`

## 已知限制 / 能力声明

- **决策面仅到"提案"为止**：`ExportProposal` 行无任何传输/支出副作用——
  无 payload 字节、无 recipient、无金额字段；status 域无
  submitted/executed 终态。CS-1002（transformed payload + disclosure
  review）及其后票据未做。
- **云能力恒 `not_configured`**：无 provider/account/budget 配置面，
  egress=deny；即便未来出现云凭据，其存在也不构成批准（§20.2）。
- **可行性 = 保守上界兼容检查**：`est.high` 对 `capacity − reserve`；
  "更慢"绝不等于"不可能"（busy 维度单列）；未观测维度记
  `missing` 而非假设充足。估计值必须由 spec 声明（bounded），
  无发明吞吐/样本计数。
- **material_needs_approval 配置**：即使可容纳也不救可行性——
  实质质量变更需人工批准路径，决策面不自动启用。
- **提案批准路径未实现**：`required_capability=approve_export` 已
  绑定 digest，但人工批准/拒绝 UI 属后续票据；本票中提案永远
  停在 proposed。
- **UI 为最小决策面**：§22.4 状态覆盖（loading/error/empty/
  feasible/infeasible-proposed），无批准按钮。
