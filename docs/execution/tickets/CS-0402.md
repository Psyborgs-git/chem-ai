# CS-0402 — Implement capabilities, admission and budgets

**Status:** completed
**Phase:** P04 · **Owner:** runtime

## Changed files

- `workers/common/resources.py` — dependency-free hardware probe:
  OS/arch, Python/node/engine runtime presence, logical+physical
  CPU, RAM total/available (sysconf + `hw.memsize` on Darwin),
  disk free, memory model (`unified` detected on Apple Silicon,
  `unknown` elsewhere until proven discrete), GPU inventory via
  `nvidia-smi` when present (read-only probes with fixed argv,
  timeouts, and `noqa` justifications), an honest `isolation` map
  that reports *absent* controls rather than claiming them, and an
  observation timestamp. Every unobservable field is `None` —
  never fabricated.
- `services/studio-api/src/studio/persistence/models.py` +
  `migrations/versions/0014_resource_admission.py` —
  `ResourceGroup` (named pool: `capacity` minus `reserve` headroom
  is the schedulable envelope) and `ResourceReservation`
  (transactional hold, one active per run, expiring so a lost
  worker cannot hold capacity forever).
- `services/studio-api/src/studio/domain/runs/admission.py` —
  `AdmissionService`: bounded envelope validation (integers only,
  `wall_seconds` capped at 7 days), per-dimension check against
  `capacity - reserve - live reservations` under a `FOR UPDATE`
  group lock (no overselling), admit → reservation + enqueue in
  one transaction, deny → `run.blocked` with explicit reasons and
  `next_step="export_review_proposal"` — a human review proposal,
  never a submission. Unobserved capacity dimensions are reported
  `missing`, not assumed sufficient. `release`/`sweep_expired`/
  `utilization` complete the lifecycle.
- `services/studio-api/src/studio/domain/runs/queue.py` —
  `RunService.block` (`requested/awaiting_approval → blocked`,
  records reasons on `run.error`, outbox `run.blocked`); retry
  path now refuses to requeue when cancellation is pending.
- `services/studio-api/src/studio/api/graphql/schema.py` —
  `computeResources` JSON query (observed hardware + per-group
  capacity/reserve/reserved), gated by `request_compute`.
- `apps/studio-web/src/features/compute/` — `ComputePanel`
  (`/compute`, nav entry): hardware report with explicit
  `unknown`/`unobserved` rendering and per-group
  capacity/reserve/reserved/available tables; an empty group list
  states plainly that heavy runs will be reported blocked.
- `services/studio-api/tests/unit/test_resources.py`,
  `tests/integration/test_admission.py`,
  `tests/security/test_admission_security.py`.

## Honest status / boundaries

- The probe runs in the API process; it reports what the host
  exposes. `isolation.network_deny_enforced` is `false` — this
  host cannot verify that control, and it is not claimed.
- Groups are configured explicitly (`ensure_group`); there is no
  automatic group provisioning from the hardware report yet, and
  no background scheduler invokes `sweep_expired` — callers drive
  it.
- `export_review_proposal` is a string marker, not a wired export
  flow — the export-review subsystem lands in a later ticket, and
  nothing here submits anywhere.
- Reservation expiry releases *capacity*; reconciling the run's
  own status is the reconciler's job (CS-0401).
