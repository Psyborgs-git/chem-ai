## Acceptance mapping

- **AT-0102-1** (viewer/agent denied approval): `ctx.require` on
  `approve_experiment` / `approve_export` / `approve_model` raises
  `FORBIDDEN` for viewer and agent principals — including an agent
  that holds a *direct* `PrincipalCapability` grant for an approval
  (the `effective_grants` ceiling strips it before the check).
- **AT-0102-2** (foreign origin mutation rejected, no state change):
  `POST /api/auth/setup` with `Origin: https://attacker.example` →
  403 and zero `principals` rows in the DB (verified by count query).
  Foreign `Host` header also → 403. Same-origin setup+login+logout
  flow completes end-to-end; second `/setup` → 409.
- **AT-0102-3** (cross-workscope denial): a principal id from
  workspace A passed to `load_context` for workspace B →
  `UNAUTHENTICATED` (no existence leak); workspace-scoped project
  query returns nothing for the other workspace.

## Limitations

- Single-workspace loopback topology (E04). Multi-workspace is a
  later reviewed change; `_default_workspace` picks the oldest
  workspace.
- Session cookie `secure=False` is correct for http loopback only;
  any non-loopback deployment must set TLS + `secure=True`.
- `docs/chemistry-studio/` (vendored spec + its `.venv-validation`)
  is excluded from project lint — it is upstream material, not
  first-party code.
