## Acceptance mapping

- **AT-0103-1** (traversal/symlink archive rejected outside vault):
  tar `../evil.txt`, tar symlink member, zip `../../evil.txt`, and a
  zip mislabeled `text/plain` are each rejected at `finish` with
  `VALIDATION`; post-conditions asserted — zero files under
  `blobs/`, zero `.part` files under `.staging/`, artifact
  `upload_state=aborted`, `review_state=rejected`. Member-level unit
  tests cover name taxonomy, symlink zips (unix mode flag), member
  count caps.
- **AT-0103-2** (interrupted upload retried with same identity):
  `finish` called twice returns the same `artifactId`, same verified
  `checksumSha256`, exactly one blob on disk; retried `finish` with a
  *different* checksum → `CONFLICT`; PUT to a committed upload →
  `CONFLICT`. Declared-checksum mismatch aborts + discards staging.
- **AT-0103-3** (unauthenticated artifact URL): `GET
  /api/artifacts/{id}/content` with no session → 401, body contains
  no payload bytes and neither the vault path nor `storage`; a
  session from a *different* workspace → uniform 404; a `viewer`
  principal initiating upload → 403; vault `open_blob`/`blob_path`
  with `..` keys raise before touching the FS.

## Limitations

- `Content-Length`-free chunked uploads resume by re-PUT; a partial
  staging file survives until `abort` or TTL cleanup (by design —
  staged cleanup, no orphaning of committed records).
- Encrypted-at-rest vault (§21.3 "where implemented") is not yet
  implemented — the control is recorded as `unavailable`; OS/FDE
  remains the stated prerequisite for sensitive deployment.
- Download authorization is capability+scope based; per-artifact ACL
  lists arrive with project membership work (P02).
