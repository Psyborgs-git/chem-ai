## 实现内容

### 1. `workers/inference/model_loading/` — 兼容性校验（stdlib + 隔离双轨）

- `contracts.py`：纯 pydantic（`extra="forbid"`，无 torch import）——
  `BaseIdentity`（base_model_id/architecture/init_seed/**base_sha256**/
  license_id）、`TokenizerIdentity`（kind/sha256）、`AdapterBinding`
  （训练时实测记录的 base_sha256 + tokenizer_sha256 + architecture）、
  `AdapterIdentity`（artifact/sha256/method/config/**base_binding**）、
  `LoadRequest`、`CompatibilityCheck`、`ParityReport`、
  `LoadValidationReport`（`status=compatible|incompatible`、
  `mode=stdlib|isolated|stdlib+isolated`、`load_verified` 诚实位）。
- `verify.py`：stdlib 结构层——`safetensors_header`（8 字节 LE 长度 +
  UTF-8 JSON，64MB 上限）、`structural_checks`（**adapter_base_hash /
  adapter_tokenizer_hash / architecture_match**——即 §18.4 的结构性
  兼容定义：注册 base+tokenizer 摘要 vs 训练时记录的 adapter 绑定）、
  `checksum_check`（live 字节 vs 注册摘要）、`safetensors_check`；
  `serving-bundle-v1` 派生格式：canonical JSON 内嵌全部身份 +
  `payloadB64` adapter 字节 + `conversionSteps`，独立摘要入库；
  `bundle_parity` 重算内嵌摘要 vs 注册 + payload 再哈希 vs adapter
  摘要；`validate_structural` 一次跑齐全部检查。
- `runner.py`：容器内进程——从 cwd 读 `request.json`
  (+`adapter.safetensors`/`bundle.json`)，先跑同款
  `validate_structural`，再 `torch.manual_seed(init_seed)` 按
  `BASE_ARCHITECTURES` 重建 PicoGPT、实测 `state_dict_sha256` 对照注册
  摘要、peft `set_peft_model_state_dict` 真载 adapter、`_probe_digest`
  （固定输入 → logits sha256）；bundle 路径对 payload 重走一遍并比对
  probe digest（`isolated_parity`）；末行输出报告 JSON。
- `runtime.py`：`ModelLoadRuntime.validate` —— stdlib **永远先跑**；
  `chem-studio-model-load:0.1.0` 镜像在场时经 `ContainerBackend`
  （`--network none`、只读根、UID 65534、cap-drop ALL、no-new-privileges、
  tmpfs、`ExecLimits{wall=240,cpu=180,mem=2GiB,pids=64,out=2MiB,
  file=256MiB}`）跑 runner 并以隔离报告为准；无镜像时返回标注
  `load_verified=False` 的 stdlib 报告——能力降级但**结构门不放水**。
- `Dockerfile`：与 sft 同构（python:3.12-slim + 同一份 41 包
  `requirements.lock`、torch+peft+safetensors 全钉、`HF_HUB_OFFLINE=1`、
  `TRANSFORMERS_OFFLINE=1`、`PYTHONPATH=/opt/studio`）。

### 2. `domain/learning/models.py` — ModelRegistryService（§17.5/§18.4）

- `register`：`CAP_MANAGE_MODELS`；读 run spec（base 身份）+
  `result.json`（训练实测 base/tokenizer/adapter sha256——**绑定来自
  训练实测而非调用方声称**）+ run.lineage（snapshot→run→adapter→
  release）；建 `ModelRelease`（state=registered）并**立即**做首次
  `_validate_now`（compatible→validated）。
- `convert`：由注册对派生 `serving-bundle-v1` 工件（vault 私域、
  `source_kind="derived"`、独立摘要），`bundle_parity` 当下评估并记入
  conversion 记录；parity 不过 → `MODEL_INCOMPATIBLE`。
- `approve`：`grant(action="model_release")`——`CAP_APPROVE_MODEL`
  仅人类持有；bound_inputs 钉死 release id + 全部摘要 + conversions。
- `promote`：**唯一使 `promoted` 可达的路径**——同一事务内：capability
  + run 在 `candidate_release` + `require_valid` 复核 grant +
  **全新 `_validate_now` 必须 compatible** + `serving_pointers` 行
  `SELECT … FOR UPDATE` + 旧 promoted→superseded + pointer 原子切换
  （revision+1）+ run.state→promoted + audit。
- `rollback`：`FOR UPDATE` 同行原子回迁——显式 release 或最新
  superseded 为 known-good 目标；重校验 + 要求目标在 `_SERVABLE`；
  revision+1、reason="rollback"；**不删行、不改 lineage、不动审计史**。
- `bind_session`（serving-request 入口）：`CAP_READ_PROJECT`；session
  有 pin 用 pin、无 pin 落回 pointer、pin 为 NULL 时首次成功 bind 后
  **闩锁** pin（覆盖 registry 上线前已开的会话）；目标非 `_SERVABLE`
  或全新校验不过 → `MODEL_INCOMPATIBLE`。
- `pin_session_start`（`memory.py` `start_session` 钩子）：会话创建即
  把当时 pointer 写入 `session_model_pins`（可 NULL）——**指针移动
  永不改写已开会话**。

### 3. 持久化 + wiring

- `model_releases`（state CheckConstraint：
  registered|validated|promoted|superseded|rejected|revoked；scope 索引；
  复合 FK→research_tasks/training_runs/dataset_snapshots/principals）、
  `serving_pointers`（每 workspace 一行、revision 单调递增、
  行级锁保证指针移动原子性）、`session_model_pins`
  （workspace+session 唯一、复合 FK→research_sessions）。
- `sft.py`：`_ALLOWED["candidate_release"]` 增至 `{"promoted",
  "rejected"}`；`transition()` 对 `promoted` 仍抛
  `MODEL_NOT_PROMOTABLE`——直接调用永远到不了 promoted。
- `application/approvals.py` `require_valid`：修复同事务多 grant 的
  不确定性——旧实现 `created_at desc, id desc` 在同 `func.now()` 事务
  内靠随机 uuid 决胜；现取**绑定摘要与请求输入精确匹配的最新
  approved grant**，无匹配再按 newest 判 forbidden/STALE。
  语义收紧而非放宽（过期/撤销/绑定复核原样）。
- `errors.py`：`MODEL_INCOMPATIBLE`。

### 4. GraphQL + UI

- Query：`modelReleases(taskId)`、`modelRelease(id)`、`servingPointer`、
  `sessionModelPins(taskId)`；Mutation：`modelReleaseRegister/
  Validate/Convert/Approve/Promote/Rollback`、`sessionModelBind`
  （错误走 `UserError{code,message,safeDetails}`）。
- `features/learning/models/{operations.ts,ModelsPanel.tsx}`：registry
  列表（身份摘要 + 状态 + validation checks + conversion parity）、
  serving pointer 卡（releaseId/revision/reason + rollback）、
  per-session pin 列表 + serving-bind 按钮、诚实 capability 标注
  （baseModel/engineCapability/dataStatus=fixture_only/
  scientificStatus=not_validated/promotion=gated）；TaskWorkspace 加
  `"models"` section。

## 已知限制 / 能力声明

- **capability 标注**：`engineCapability` 随 `chem-studio-model-load`
  镜像在场与否标注 `live|stdlib_only`——无镜像时 `mode=stdlib`、
  `load_verified=False`，结构兼容门仍然强制执行；
  `dataStatus=fixture_only`、`scientificStatus=not_validated`（兼容性
  验证≠科学验证）；`promotion` 标注「approved serving pointer only —
  evaluation gates are CS-0803」。
- 注册只接纳含 `adapter+result` 持久化产物的非 draft/failed 运行；
  没有 adapter 工件或 result 缺摘要 → CONFLICT（无从建立绑定）。
- 集成测试以 `available()→False` 钉死 stdlib 层（无 docker 亦可验）；
  隔离层在 `tests/engines/model_loading`（4 项）实测——镜像在场时
  `engineCapability=live`、真实 torch load + probe digest + bundle
  isolated parity 全过。
- `serving-bundle-v1` 是 canonical JSON 内嵌格式（含 payload）——
  面向 fixture 基座的交换格式；更重的打包/分片留给 U13。
- 评估/promotion-gate（CS-0803）、RL（P09）、CS-0506（U16）明确未做。
