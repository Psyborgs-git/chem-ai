**Status:** completed
**Phase:** P01 · **Owner:** controller

## Changed files

- `services/studio-api/src/studio/persistence/models.py` — five new
  workspace-scoped tables: `IdempotencyRecord`
  (unique `workspace_id+operation+key` per §5.x), `OutboxEvent`,
  `OutboxDelivery` (per-consumer dedupe ledger), `Approval`
  (envelope + bound digest + expiry + revocation), `AuditEvent`
  (minimal metadata). All carry composite workspace scope FKs where a
  principal is referenced.
- `services/studio-api/migrations/versions/0004_commands_approvals_outbox.py`
  — same shape in SQL plus scoped indexes.
- `services/studio-api/src/studio/application/idempotency.py` —
  `canonical_json`/`request_digest` (sorted-key sha256) and
  `run_idempotent(db, ctx, operation, key, payload, fn)`: existing
  record + same digest → stored response returned (fn never re-runs);
  different digest → `IDEMPOTENCY_MISMATCH`; unique-race loser rolls
  back and returns the winner's result. `fn` executes inside the
  caller's transaction — domain change + record + outbox events
  commit or roll back together.
- `services/studio-api/src/studio/application/approvals.py` —
  `grant` (requires the action's approval capability; agents can
  never hold one), `require_valid` (re-validates at *execution*:
  revoked → `FORBIDDEN`, expired → `APPROVAL_EXPIRED`, bound-digest
  drift → `APPROVAL_STALE`, missing/rejected → `FORBIDDEN`),
  `revoke`, `bound_digest`. Approval binds the canonical digest of
  the bound-input document — revisions, contract revision,
  method/policy versions, envelope, recipient — never a mutable
  task id.
- `services/studio-api/src/studio/events/outbox.py` — `publish`
  (same transaction), `deliver_pending` (ordered delivery; dedupe
  row + handler inside one savepoint → at-most-once per consumer
  while the stream stays at-least-once), `delivered_to`.
- `services/studio-api/src/studio/audit/log.py` — `record` for
  minimal audit metadata; a sensitive-key blocklist drops payload
  keys if they ever appear in a detail dict (belt over contract).
- `services/studio-api/src/studio/api/graphql/schema.py` —
  `taskCreate` is now a real command: optional `idempotencyKey`,
  canonical command payload, domain row + `task.created` outbox
  event + `task.create` audit event + idempotency record in one
  commit. `IDEMPOTENCY_MISMATCH` surfaces as a typed error payload.
- `packages/contracts/schema.graphql` — re-exported (137 lines).
- `services/studio-api/tests/integration/test_commands_approvals.py`
  — 16 integration tests.

## Acceptance mapping

- **AT-0105-1** (same key + same payload → original result, no
  duplicate effects): `test_same_key_same_payload_replays_result`
  proves `fn` runs once and both calls return the identical response
  with exactly one `IdempotencyRecord`. End-to-end:
  `test_task_create_idempotent_end_to_end` issues the mutation twice
  with `idempotencyKey: k-1` — same task GlobalID, one
  `research_tasks` row, one `outbox_events` row.
- **AT-0105-2** (same key + different payload →
  IDEMPOTENCY_MISMATCH): `test_same_key_different_payload_mismatch`
  at the command layer and the GraphQL variant asserting the typed
  `errors[0].code == "IDEMPOTENCY_MISMATCH"` with `task: null`.
- **AT-0105-3** (approval input revision/recipient/budget changed →
  stale + blocked): `test_valid_then_stale_blocks` — approval granted
  over bound inputs validates, then changing `revisionId`, the
  `recipient`, or `budget` each raises `APPROVAL_STALE`. Also:
  `APPROVAL_EXPIRED` (ttl), `FORBIDDEN` (revoked, missing, rejected),
  agent principal denied grant, cross-workspace approval invisible.
- **Outbox (§7.4)**: `test_dedupe_per_consumer` — second
  `deliver_pending` delivers 0; `test_independent_consumers_each_receive`
  — per-consumer ledgers; `test_event_survives_only_with_its_state` —
  rollback of the domain change removes the outbox row (no phantom
  events). `test_task_create_writes_outbox_and_audit` — the mutation
  writes `task.created` + `task.create` in one commit, and the audit
  row carries metadata only (no title/objective).

## Limitations

- Only `taskCreate` rides the idempotent path so far; other commands
  (evidence import, experiment release, export, model promotion)
  adopt `run_idempotent`/`require_valid`/`publish` as their domain
  surfaces land — the machinery is shared, not per-command.
- Outbox delivery is in-process polling (`deliver_pending`); no
  background worker or LISTEN/NOTIFY yet — consumers arrive with
  the job scheduler ticket.
- Approval staleness is detected at `require_valid` call time;
  pre-emptive invalidation on bound-revision supersede is a later
  hook (needs the revision-write paths from P02).
- `expected_version` optimistic-lock enforcement is wired at the
  model layer (CS-0101) but not yet surfaced as a command argument —
  it arrives with revision-writing mutations.
- Concurrent same-key insert is handled (rollback + return winner)
  but the lose-the-race path returns `CONFLICT retryable` if the
  winner hasn't committed yet — single-process deployments never
  hit this.
