## 实现内容

### 1. 有界事件流（seq + 断线恢复 + 快照回退）`§8`

- `outbox_events` 增加单调 `seq BIGSERIAL`（迁移 `0016_outbox_seq`），
  为 SSE 客户端提供可恢复的游标；新增
  `(workspace_id, aggregate_id, seq)` 复合索引。
- `studio/api/events/routes.py`:
  - `GET /api/events/stream?channel=session|task&id=<uuid>&since=<seq>`
    — `text/event-stream`；每条事件 `id: <seq>` + `event: <type>`；
    `Last-Event-ID` 头优先于 `since` 参数；每连接上限
    500 事件 / 55s + 心跳，超时关闭由客户端自动重连。
  - `GET /api/events/snapshot?channel=…&id=…` — 返回权威当前状态
    （session→全部消息；task→runs+attempts）+ 对应 `maxSeq`。
  - 两个端点均解析 `ServiceContext` 并对所属 project 执行
    `ctx.require(CAP_READ_PROJECT, project_id)`，不会跨 scope 泄露事件。
- 事件来源复用事务性 outbox：
  - `TaskMemoryService.post_message` 新增
    `session.message.posted` 发布（携带 taskId/messageId/kind/content/refs）；
  - `RunService._transition` 成为唯一状态转换出口，新增
    `run.status.changed` 发布（runId/taskId/status）；
  - 既有 `run.attempt.enqueued`/`run.cancel.requested`/`run.blocked`
    负载补充 `taskId` 以支持 task 频道聚合。

### 2. 真实并发缺陷修复（e2e 暴露）

原实现对 `/api/events/stream` 使用 `Ctx` FastAPI 依赖：
依赖级 `db_session` 在响应存续期间保持打开，而
`authenticate_token` 的 `auth_sessions.last_seen_at` UPDATE 在该
会话内持有**行锁**。一条 SSE 连接挂起 55s 期间，任何其他请求的
auth 更新都阻塞在该锁上；同步 SQLAlchemy 调用又在事件循环线程
执行，导致整个 uvicorn 冻结（healthz 无响应、GraphQL 挂起）。

修复：`stream`/`snapshot` 均改为手动短会话解析上下文 —
`build_context` → `_authorize` → `db.commit()` → `db.close()`，
全部在返回 `StreamingResponse` 之前完成；流内每次轮询独立开关会话。

### 3. 前端 `apps/studio-web`

- `src/features/research/stream.ts`: `openStream()` EventSource 封装
  （named-event 监听、Last-Event-ID 自动续传、onError 置重连态）。
- `src/relay/network.ts`: `fetchEventSnapshot()` + `rawUuid()`
  （GlobalID→uuid 解码）；REST 传输统一走该模块，满足 §8.2 边界。
- `src/features/research/SessionStream.tsx`: 快照先行 → SSE 追加，
  messageId 去重；消息种类区分渲染 —
  `message`/`proposal`(待评审)/`rationale`/`tool_call`(action requested)/
  `tool_result`（按 `ok` 渲染 action completed/failed，
  **不信任 assistant 文本**，AT-0406-2）。
- `src/features/runs/RunsPanel.tsx` + `operations.ts`: task 维度
  runs 列表，`requested/awaiting_approval/queued/running/
  cancel_requested→"cancel requested…"/blocked/interrupted/
  timed_out/failed(无 resultSummary→"failed — output unavailable")/
  succeeded` 状态徽章；可取消 run 显示 cancel 按钮；
  `cancel_requested` 保持到终端 `cancelled` 确认为止（AT-0406-3）；
  task 频道事件去抖触发 Relay `fetchKey` 网络重取。
- `TaskWorkspace` 新增 `runs` 分区；`ResearchPanel` 每个 session
  挂载 `SessionStream`（`<details><summary>stream</summary>`）。
- GraphQL 新增：`taskRuns` keyset 连接、`Run`/`RunAttempt` Node 类型、
  `runs.request`/`runs.requestCancel` 命名空间（schema.graphql 已同步）。

## 已知限制 / 能力声明

- SSE 为**消息级**事件流（post_message 时发布），非模型 token 级流式
  输出；llama.cpp 推理本身仍是整段返回。这与 spec "bounded event
  streams with sequence IDs" 一致，token 级流式属后续优化项。
- 事件流以 outbox 为准：未发布到 outbox 的状态（例如直接改库）不会
  出现在流中；UI 另有快照端点兜底。
- `_stream` 内同步短查询在事件循环上执行（每条 SQL 亚毫秒级），
  本地单用户语义下可接受；若未来多用户并发需评估工作线程隔离。
- `snapshot`/`stream` 依赖 outbox seq；`run.status.changed` 仅覆盖
  `RunService._transition` 路径（该服务内所有状态迁移的唯一出口）。
- 前端 SSE 为浏览器 EventSource，仅支持 GET+cookie — 与现有会话
  认证模型一致。
