# CS-0404 — Integrate real RDKit and deterministic verifier

**Status:** completed
**Phase:** P04 · **Owner:** chemistry
**Requirement:** REQ-0404 · handoff §12, §13, §16

## Changed files

- `packages/engine-adapters/rdkit/engine_adapter_rdkit/` — new adapter
  package (write scope):
  - `worker.py` — self-contained in-engine worker: parse (un-sanitized
    first so parse vs sanitize are distinct typed stages), sanitize,
    then descriptors + canonical SMILES + InChIKey + formula +
    `rdBase.rdkitVersion`. Output is one typed JSON document; failure
    is `PARSE_FAILED` / `SANITIZE_FAILED` / `EMPTY_INPUT` /
    `ENGINE_UNSUPPORTED_INPUT` / `INTERNAL` / `ENGINE_UNAVAILABLE` —
    a descriptor is never fabricated.
  - `adapter.py` — `RDKitAdapter`: capability discovery (container
    image first, native restricted subprocess second, else honest
    `available=False`), typed `StructuralResult` (evidence class
    `descriptor`, never lab proof) or `EngineError`. The recorded
    version is always the engine's own report.
- `infra/images/rdkit/Dockerfile` — `chem-studio-rdkit:2026.3.6`,
  linux/amd64 (the platform matrix path — rdkit ships no macOS x86_64
  wheel), version pinned to the lockfile.
- `services/studio-api/src/studio/domain/candidates/verification.py` —
  `VerificationService.evaluate_candidate`: deterministic formulation
  checks (duplicate lines, missing/invalid amounts, declared-total vs
  sum within tolerance), identity/structure checks (unresolved
  structure reported `unknown`, reviewed structures run the real
  engine), eligibility findings, and a per-metric **closure** table
  evaluating `metrics[].required_evidence` against the evidence
  classes actually present — `lab_measurement`/`replication`/
  `physics_prediction`/… requirements are reported *missing*, never
  satisfied by a structural pass. Emits a `candidate.verified` audit.
- `services/studio-api/src/studio/api/capabilities.py` — the rdkit
  engine status now comes from the adapter's own probe (native OR
  container), with the real version.
- `Makefile` — `test-engines` accepts the container image as a real
  engine path in addition to a native `--extra engines` install;
  neither present → `UNAVAILABLE` exit 2 (unchanged contract).
- `pyproject.toml` — adapter package added to hatch/mypy/ruff paths;
  mypy override `ignore_missing_imports` for `rdkit.*` (optional dep
  absent in the base profile).
- `services/studio-api/tests/engines/test_rdkit_adapter.py`,
  `services/studio-api/tests/integration/test_verification.py`.

## Honest status / boundaries

- **Live:** real RDKit 2026.03.6 via `chem-studio-rdkit` container —
  `--network none --read-only --cap-drop ALL`, engine-run evidence is
  `descriptor` class only.
- **Unavailable natively:** this macOS x86_64 host still has no rdkit
  wheel; `capabilities()` reports the container as the detail, and CI
  (`engines` job, ubuntu-24.04) exercises the native path via
  `--extra engines`.
- The verifier produces a decision *input* — a human reviewer still
  closes tasks; `evaluate_candidate` needs `request_compute`.
- `descriptor` is not in the contract `required_evidence` enum — by
  design a structural check can never satisfy a metric endpoint; the
  packet surfaces that explicitly rather than bending it.
- No GraphQL surface was added for verification packets (write scope);
  they are service-level + audit-visible for now.
