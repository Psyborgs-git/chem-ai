## Acceptance mapping

- **AT-0101-1:** frozen revision UPDATE of payload →
  `immutable_revision` DB error; DELETE rejected; only
  `status → superseded` allowed (verified: payload unchanged, new
  revision gets `revision=2`, new row id).
- **AT-0101-2:** `compare_and_swap` on same `expected_version=1` —
  writer 1 commits, writer 2 raises `DomainError(REVISION_CONFLICT)`;
  stored row shows writer-1 values, version=2.
- **AT-0101-3:** contract revision inserted with `workspace_id` of a
  different workspace than its task → `IntegrityError` (composite
  scope FK). Same for task→project across workspaces.

## Migration notes

`0001_initial_core` covers §26.2 groups 1–2. Later groups get their own
revisions in dependency order (artifacts→0002, events/idempotency→0003,
materials→0004, …). Downgrade drops all objects; production rollback
policy is roll-forward per §26.2.
