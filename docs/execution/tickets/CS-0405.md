**Status:** completed

## Changed files

- `workers/inference/runtime.py` + `__init__.py` — provider-neutral
  local runtime (§10.2, U08/U13):
  - `ModelSpec` — pinned model: `gemma-2b-it`, sha256
    `c1864a5e…57d12` (verified inside the container at handshake),
    license `gemma-terms-of-use`, chat template family `gemma`,
    context 2048. No automatic model downloads (U13) — the GGUF
    comes from the local store, copied once into the `chem-models`
    Docker volume (native ext4 inside the VM; the macOS bind-mount
    mmap path stalls).
  - `LlamaCppRuntime` — runs `ghcr.io/ggml-org/llama.cpp:server`
    (build 11382) on a **loopback-only** published port with
    `--read-only --cap-drop ALL --security-opt no-new-privileges`;
    start/stop/health/generate.
  - `handshake()` — executed, not declared: model sha256 verified
    in-container, chat template exercised with a real request, and a
    structured-output probe must return parseable constrained JSON.
    Anything short → `available=False` with the real detail.
  - Structured output uses a direct **GBNF grammar** — this server
    build's `response_format`/`json_schema` sampler fails with
    "Failed to initialize samplers" (verified). `TURN_GRAMMAR`
    (call|answer), `ANSWER_GRAMMAR` (answer only), `JSON_MINI`.
- `services/studio-api/src/studio/application/agent_tools/`:
  - `registry.py` — closed catalog of 6 typed tools with JSON-Schema
    inputs, all calling the same domain services as the UI:
    `search_evidence`, `read_candidate_revision`,
    `validate_formulation`, `propose_candidate_patch`,
    `request_calculation`, `summarize_task_evidence`. **No** export/
    approve/promote/close verbs exist — the catalog is the boundary.
    `ToolDispatcher`: schema validation, per-turn call/wall budgets,
    32KB result cap, `untrusted` flag on outputs, typed errors.
  - `turn.py` — `AgentTurnRunner`: user message → loop
    generate→tool→result (persisted as `tool_call`/`tool_result`
    session messages) → final assistant message. Small-model
    hardening: a repeated tool name stops the loop and forces the
    answer with `ANSWER_GRAMMAR`; unstructured output is kept
    verbatim with an `unstructured` flag; exhausted budgets end with
    explicit reason — never a silent stop.
- `infra/images/llamacpp/Dockerfile` — optional baked-model image
  (sha256 checked at build); not required when the `chem-models`
  volume is used.
- `tests/engines/test_inference.py` (4 tests — real model),
  `tests/integration/test_agent_turn.py` (6 — plumbing + degraded),
  `tests/security/test_agent_tools.py` (4 — boundary).
- `pyproject.toml` — mypy override for `jsonschema` stubs.

## Honest status / boundaries

- **Live:** llama.cpp `ghcr.io/…:server` + pinned `gemma-2b-it`
  (sha256-verified) on `chem-models` volume, loopback-only port,
  hardened container flags. Inference is real and verified.
- **Degraded by design:** no runtime → `model_unavailable`; manual
  workflow unaffected (AT-0405-3).
- **Honest limits:** the egress from the inference container is not
  network-denied (loopback-published server needs inbound only, but
  the bridge NAT technically allows egress) — it has no credentials,
  mounts, or tools inside; the agent boundary is the closed tool
  catalog. Model is 2B — turns are bounded by budgets/dedupe, and a
  stalled turn ends explicitly rather than running forever.

  the adapter uses GBNF `grammar` (verified working) and reports it.

  `docker image prune` removed `chem-studio-rdkit` — the image was
  rebuilt (`docker buildx build --platform linux/amd64 -t
  chem-studio-rdkit:2026.3.6 infra/images/rdkit`) and all engine
  tests pass again.
