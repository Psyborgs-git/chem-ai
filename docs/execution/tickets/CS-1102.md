### 1. `tests/integration/migrations/` — 三个 AT 的实测驱动

- `conftest.py`：每测试用 throwaway `PostgresContainer(16.10-alpine)`
  起 `m_*` 一次性库；`STUDIO_DATABASE_URL` + `STUDIO_PGTOOL_CONTAINER`
  注入子进程；`LEGACY_BASE_REV="0012_evidence_revocation"`（升级链路
  0013→head）；`alembic_upgrade`/`alembic_version`/`alembic_repo_head`
  等子进程封装。
- `legacy_seed.py`：**真实** populated 旧版库——rev-0012 下写入 60 个
  对象：3 principal（user/reviewer/agent，含 credential_hash）、4 条
  capability（含一条 scoped `review_science` + 一条 `revoked_at` 已置的
  `request_compute`）、2 auth_sessions（一吊销）、project/task、
  contract rev1 frozen + rev2 draft（真 `content_hash`）、closure
  decision、4 artifact（含 derived `source_artifact_ids` + 一条
  revoked 工件——字节仍入 vault）、import_batch(parsed)+2 accepted
  extracted_records、claim1(accepted document_claim)+claim2(proposed)
  +supports link、2 chunks（active/revoked）、source_revocations 墓碑、
  retrieval_manifest+cache、research_session+messages+question+summary+
  context_manifest、formulation 家族+版本链+process+candidate
  (accepted_for_research/eligible_for_approved_experiment)、3 approvals
  （contract.freeze/formulation.accept/export.review-rejected，真
  `bound_digest`）、4 outbox_events（验证 0016 seq 回填）。
  `seed_head_extras` 再加 CS-0802 链：dataset_snapshot(frozen)→
  training_run(completed)→model_release(promoted)→serving_pointer→
  session_model_pin + run/feasibility(infeasible)/export_proposal。
  `snapshot`/`compare_snapshots` 做行级 sha256 快照对比（列投影——
  升级后新增列不进对比）。
- `test_populated_upgrade.py`（AT-1102-1）：0012→head 升级后——
  全表投影快照零差异；contract/candidate 的 `content_hash` 与 approval
  `bound_digest` 均现场重算通过；每行 artifact 的 checksum == vault
  字节 sha256；11 组 FK 引用 join 全部解析；`load_context` 下 owner
  `administer_workspace`、reviewer `approve_experiment`+仅本 project 的
  `review_science`、agent 已吊销授权仍被拒；`outbox_events.seq` 4 行全
  非空且唯一；`uq_approvals_scope_id` 存在；三个 immutability trigger
  在场；head 新表存在；吊销墓碑完好。
- `test_interrupt_resume.py`（AT-1102-2）：
  - `test_migration_kill_leaves_atomic_state`——`alembic upgrade head`
    子进程跑到 0.15s 时 SIGKILL：版本仍 0012、无 `runs` 等新表、
    数据快照零变化（单事务回滚）；重跑到 head 成功且快照仍零差异。
  - `test_backfill_kill_resume_no_duplicates`——head 库 + 25 条 claims，
    backfill 跑 batch1 后 SIGKILL：checkpoint `rows_done=8`、digest 表 8
    行；resume 跑完后恰好 25 条唯一 digest；`verify` exit 0；整表重跑为
    幂等 no-op；篡改某 claim.statement 后 `verify` exit 1 且点名该 id
    为 drift。
- `test_fresh_restore.py`（AT-1102-3）：备份 → 全新库 + 全新 vault
  目录还原 → `recovery_check` 12 项全 PASS（`--json` 断言）；逐表计数
  与 serving 指针回指一致；破坏型回放——删 vault blob + DROP
  `session_model_pins` + 篡改 approval digest——`recovery_check` exit 1
  且逐条列出 3 个 missing 项（kind+id）。

### 2. `infra/local/` 入口

- `backup.py`（小改）：pg 工具回退现在带版本守卫——host 客户端
  `major < server_major` 时自动走 `docker exec`（本机 pg_dump 14 vs
  server 16，旧逻辑会必然失败）；容器名改经
  `STUDIO_PGTOOL_CONTAINER`（默认 `chem-studio-postgres`）；容器内
  DSN 重写沿用 DSN 的 user/pass 而非硬编码。`make backup-test`
  (AT-0505-1) 实测仍绿。
- `resumable_backfill.py`（新增）：checkpoint 化证据摘要回填——
  `ops_backfill_checkpoints`+`ops_record_digests`（append-only，
  PK=(entity_table,entity_id)，`ON CONFLICT DO NOTHING`）；每批
  单事务提交 digest+checkpoint；`--max-batches` 与 SIGTERM/SIGINT
  →exit 3；`verify` 重算全部源行 vs 已发 digest，报
  orphan/drift/missing → exit 1；`status` 打 checkpoint+pending。
- `recovery_check.py`（新增）：还原后系统级完整性校验，12 组检查
  （alembic_head/required_tables/artifact_blobs/derived_lineage/
  serving_chain/training_lineage/scopes/key_material/approvals/
  export_proposals/evidence_refs/revocation_tombstones，CS-1003
  export broker 表存在时才启用 `export_broker`）——缺项带 id 全量
  枚举，exit 1；`--json` 输出机器可读报告。

## 已知限制

- **CS-1003 表覆盖是条件式的**：基线分支当前的 broker 包
  （`infra/cloud/broker`）DB-free、尚无迁移；`recovery_check` 对
  `export_*` broker 表（jobs/receipts 等）采用存在才校验的策略，
  该 lane 落地迁移后自动生效。`export_proposals`（head 已存在）的
  引用完整性已实测校验。
- `ops_record_digests` 仅覆盖 `evidence_claims`（科学记录面的一种
  示范性可续跑回填）；后续表接入按同一 checkpoint 契约扩展。
- 保留窗口未配置（§21.6 本就要求"显式占位"）：当前无任何定时清理，
  吊销内容的字节仍随备份传播——已在 recovery.md §4 逐条写清。
- 测试库为 testcontainers 自举，不依赖 compose；CI 若无 docker
  则按 `integration` marker 跳过（与既有 suite 一致）。
