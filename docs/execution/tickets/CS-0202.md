# CS-0202 — Implement quantities, basis and missingness

**Status:** completed
**Phase:** P02 · **Owner:** controller

## Changed files

- `services/studio-api/src/studio/domain/materials/quantities.py`
  — the §6.1/§6.3 value layer:
  - `UNIT_REGISTRY`: whitelisted unit ids per dimensional category —
    mass, volume, amount, molar mass, density, temperature *absolute*
    vs *delta* (distinct dimensions — a difference is not an
    absolute), pressure, viscosity (mPa·s vs Pa·s, the §6.1 example),
    and mass/volume/mole fractions kept as *separate* dimensions so
    no implicit transform exists between them. Entries carry affine
    `(pre_offset, num/den, post_offset)` so °F's 5/9 stays exact.
  - `Quantity` (frozen): authoritative `Decimal` value + unit +
    `basis` (`as_supplied`/`active_solids`) + `context`
    (`formulation_amount`/`application_dosage`) + `original_text` +
    an immutable conversion `provenance` log. `create` rejects
    floats (a binary float is never authoritative), NaN/Infinity,
    unknown units, unknown bases; fraction dimensions require a
    basis ("a concentration without basis is incomplete").
  - `convert`: same-dimension factor/affine conversions are
    unconditional; mass↔volume crosses only through a `Density`
    carrying value+unit+conditions+source+applicability (all four
    metadata mandatory); mole↔mass crosses only through an explicit
    molar-mass `Quantity`; every other cross-dimension pair is
    `INVALID_UNIT` — transforms are never guessed.
  - `change_basis`: requires an explicit reviewed transform
    `Quantity`; never silently rebases.
  - `MeasurementValue`: `numeric | interval | below_detection |
    above_quantification | ordinal | categorical | missing`.
    Intervals validate shared dimension and bound order; ordinal/
    categorical carry `scale_revision_id`; `missing` requires a
    reason from the contract enum (incl. `cancelled`);
    `repeat_kind` preserves same-sample/batch/lab/timepoint.
    `feature_scalar()` returns `None` — *exclude* — for everything
    but numeric (intervals only via explicit midpoint opt-in), so
    censored and missing values are never zero-filled.
  - `check_declared_total`: sums same-dimension amounts against a
    declared total inside an explicit tolerance →
    `COMPOSITION_TOTAL_INVALID` outside it. Nothing is normalized.
  - `to_dto`/`from_dto` emit exactly the `Quantity`/`MeasuredValue`
    shapes in `packages/contracts/domain.schema.json` (plain-decimal
    strings — the pattern forbids exponents); `to_dict`/`from_dict`
    is the fuller internal serialization with provenance/context.
  - `REPEAT_TYPES`, `MISSING_REASONS`, `FAILURE_REASONS` constants
    mirroring §6.3/§6.4.
- `services/studio-api/tests/unit/test_quantities.py` — 32 tests:
  blocking rules, zero-fill denial, exact-decimal storage, a full
  unit-pair roundtrip grid, and `to_dto` validation against the real
  `domain.schema.json` via `Draft202012Validator`.
- `packages/contracts/` — no schema edit needed: the canonical
  `Quantity`/`MeasuredValue` DTOs already existed; the module now
  *conforms* to them, proven by validation, rather than drifting
  from them.

## Limitations

- The unit whitelist is deliberately small (pilot-relevant
  dimensions); new units are registry rows, not new code, but the
  registry *is* the gate — anything unlisted is `INVALID_UNIT`.
- Viscosity/pressure *condition compatibility* (§6.1: comparisons
  require compatible measurement conditions) is metadata-carried
  on `Quantity`/`Density` but not yet enforced by a comparator —
  that lands with measurement review in P03.
- `feature_scalar` is a projection API for adapters; the "report"
  of excluded observations (§6.3) is a caller responsibility until
  the dataset-snapshot ticket (P05) wires it.
- No currency quantities yet — §6.1 requires dated price source
  metadata; deferred to the cost-tracking ticket rather than
  stubbed.
