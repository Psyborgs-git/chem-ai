## 实现内容

### 1. `workers/training/evaluation/` — §18.1/§18.2 评测注册表 + 配对比较

- `contracts.py`：纯 pydantic（`extra="forbid"`，不可变）——
  `EvalSuiteDef`（schema_name=`eval_suite_def`：name/version/purpose/
  kind/`dev|final|safety|privacy` + tasks + thresholds + budget +
  scoring + allowed_context + review_rules + tool_versions）；
  `EvalTaskDef`（example_id/kind `task|safety|privacy`/messages/
  context_refs/subgroup/answerable/group_keys/source_record_ids/
  **target_hash**——公开定义只带标签哈希，永不带标签本体）；
  `EvalTarget`（expect `exact|contains|abstain|json_object|refusal`
  + value/required_terms/forbidden_terms 校验）；
  `EvalBudget`（max_tool_calls/max_completion_tokens/wall_seconds）、
  `EvalToolVersions`（per-tool name+digest + catalog_digest）、
  `EvalThreshold`（**value 可为 None = U14 未知**）；
  run 输出模型 `EvalArmOutput/EvalExampleResult`（**无 target 载荷**）/
  `EvalMetricSummary/EvalSubgroupSummary/EvalThresholdEval/
  EvalSafetyRegression{new_failures,candidate_failures}/EvalDenominators/
  EvalComparisonReport`（suite_digest/suite_kind/backend/tool_diff/
  results/metrics/aggregate/denominators/subgroups/thresholds/
  safety_regression/verdict `improved|flat|regressed|incomplete`）。
  `SCORING_METRICS` = correctness / abstention_appropriateness /
  schema_validity / constraint_compliance。
- `scoring.py`：backend_error/budget_exhausted/empty 输出记 **invalid**
  （永不按 0 计）；safety/privacy/refusal 任务要求拒绝 + 未泄露
  forbidden_terms；unanswerable 任务奖励 abstention_appropriateness；
  answerable 任务按 expect 判 correctness、**弃答得 0 分**
  （「永远拒答」无法取胜）；aggregate_metrics（逐指标双臂均值 + Δ）、
  aggregate_subgroups（每组 n、双臂均值、小样本标记）。
- `backend.py`：`EvaluationBackend` Protocol（`capability()→dict|None`
  + `run_example(arm,task,allowed_tools,budget)→EvalArmOutput`）；
  `UnavailableBackend` 探测 `LlamaCppRuntime`——**无运行时时诚实
  拒绝，不伪造分数**；`ScriptedBackend` 为 fixture/测试注入输出并
  记录每次调用；`default_backend()→UnavailableBackend`。
- `runner.py`：`run_matched_comparison`——`ARMS=(baseline,candidate)`
  对**同一 task 列表**逐题调 `backend.run_example`（钉死
  allowed_tools + 同一 budget）；`tool_diff` 对比冻结
  tool_versions 与 live catalog；聚合 metrics/aggregate（指标均值
  之均值）；safety_regression 只计 `new_failures`（baseline 过而
  candidate 挂）；denominators（expected/evaluated/missing/invalid/
  small_sample）；thresholds 判 pass/fail/**unknown**；按 aggregate
  Δ 与 _EPSILON 定 verdict——incomplete 保守判入。

### 2. 标签访问控制（AT-0803-2）

- `packages/policy/chem_studio_policy/capabilities.py`：新增
  `CAP_READ_EVAL_LABELS="read_eval_labels"`；新增
  `SERVICE_ONLY_CAPABILITIES` 集合——`effective_grants` 对
  **所有非 `kind=="service"` principal** 一律剥离该能力（agent 另受
  APPROVAL_CAPABILITIES 剥离不变）——用户 full-role 直授也拿不到。
- `EvaluationService._evaluation_context()`：惰性创建
  workspace 内 `kind="service"`、login=`evaluation-service` 的真实
  持久化 Principal 并授予 `read_eval_labels`——只有它能过
  `load_context` 后仍持有该能力。
- `hidden_targets(suite_id)`：`ctx.require(CAP_READ_EVAL_LABELS)`
  + `principal_kind=="service"` 双重门 + 拒绝/读取均记 audit。
- 公开路径（suite definition → GraphQL → UI）只有 `target_hash`；
  报告模型序列化里**不存在** label 载荷（单测断言 `hidden_value`
  不出现在 `model_dump_json()`）。
- agent tool catalog 为封闭集——无 label 动词，`UNKNOWN_TOOL` 层即拒。

### 3. `domain/learning/promotion.py` — EvaluationService + PromotionService

- `EvaluationService.create_suite`：`CAP_MANAGE_MODELS`（task 作用域）、
  version 自增、`EvalSuiteDef` 校验入库、capability 标注
  `{labelAccess, dataStatus=fixture_only,
  scientificStatus=not_validated, separateFromOptimizerReward}`。
- `set_labels`：仅 draft 态；`EvalTarget` 校验 + example 归属 + 去重；
  存的是**无 example_id 的标签载荷**，同时在 suite task 上盖
  `target_hash=_target_digest(payload)`——哈希可由标签行复算。
- `freeze`：要求全部任务已打 target_hash；把
  `default_registry().catalog()` 快照成 tool_versions
  （per-tool digest + catalog_digest）；定 digest、转 frozen。
  版本不可变——改动需新 version。
- `_lineage_ids`：release→run→snapshot ids + manifest recordIds +
  dataset JSONL example_id/context ids（vault 字节）。
- `_contamination`：标签值命中 prompt 文本即 finding；**final 套件
  复用**——同 lineage 兄弟 release 已在该 final suite 上评测过 →
  contamination finding（重复调参即污染）。
- `start_run`：必须 frozen + digest 复核（drift → CONFLICT）；
  `backend.capability() is None` → `ENGINE_UNAVAILABLE`（诚实拒绝）；
  run 行记 contamination；缺标签 → state=failed + error；
  `run_matched_comparison` 跑分 → 报告 JSONB 入 vault 工件
  （restricted rights）→ `_run_blockers`（hard：
  contamination/safety_regression/threshold_fail/
  held_out_not_improved/evaluation_incomplete；claim：
  unknown_threshold）→ audit。
- `PromotionService.decide(release_id)`：`CAP_MANAGE_MODELS`；
  §18.4 blocker 链（lineage_incomplete / dataset_not_frozen /
  dataset_digest_drift / run_not_candidate / validation_incompatible /
  validation_missing / missing_evaluation / suite_drift /
  contamination / safety_regression / held_out_not_improved（verdict
  ≠ improved 时）/ evaluation_incomplete / unknown_threshold（claim
  级）/ threshold_fail）；`eligible = 无 hard blocker`；
  PromotionDecision 行 + `decision_digest =
  sha256(canonical{releaseId,evaluationRunId,eligible,blockers})`
  ——**确定性**：同输入反复 decide 出同一 digest。
- `_model_card`：claims `{blanketImprovedChemistry:"not_permitted"`
  **恒为 not_permitted**、`scopedImprovement` 仅 eligible 且零 claim
  blocker 才 "permitted"}；evidence{aggregate,metrics,denominators,
  subgroups} + limitations + capability 标注。
- `approve_scope(release_id,scope,limitations,rationale)`：须先有
  decision；`grant(action="model_release_scope", bound_inputs=
  {releaseId,scope,limitations,decisionDigest,evaluationRunId})`——
  `application/approvals.py` 映射到 `CAP_APPROVE_MODEL`。
- `promote(release_id,scope,limitations)`：**全新 decide()**（确定性
  digest → `require_valid` 精确复核 grant 绑定）——见到 pass 的
  verdict 批复的 scope 与现时 scope 不一致 → `APPROVAL_STALE`；
  hard blocker → `DomainError(MODEL_NOT_PROMOTABLE,
  safe_details={blockers,decisionId})`；通过后走
  `ModelRegistryService.promote`（CS-0802 指针机器原样，
  FOR UPDATE 行锁 + superseded + audit）→ stamp approval/card →
  audit `promotion.executed`。**canary/rollback 路径即 CS-0802
  rollback**——指针机制统一。
- 持久化：`evaluation_suites`（uq(ws,name,version)+uq(ws,id)）、
  `evaluation_labels`（uq(suite_id,example_id)）、
  `evaluation_runs`（suite_digest + model_release_id +
  baseline_release_id + backend/comparison/contamination/blockers/
  capability JSONB + report_artifact_id）、`promotion_decisions`
  （eligible + blockers/model_card JSONB + decision_digest +
  approval_id）——migration `0025_evaluation_gate`
  （down_revision `0024_model_registry`）。

## 已知限制 / 能力声明

- **capability 标注**：suite/run/decision 随带
  `dataStatus=fixture_only`、`scientificStatus=not_validated`、
  `engineCapability=backend.capability()`（无 eval runtime 时
  UnavailableBackend → `ENGINE_UNAVAILABLE`、**不伪造分数**）、
  `labelAccess="evaluation service principal only"`、
  `separateFromOptimizerReward=True`；UI 同步展示该标注。
- **无真实推理后端实测**：集成测试用 `ScriptedBackend`（确定性
  注入 + 调用记录）；`LlamaCppRuntime` 在场时
  `default_backend` 才可实跑——真实化学评测属 fixture-only 声明
  范围，结论外推到真实模型须经科学评审（human release decision
  已为此门）。
- `verdict` 由 aggregate Δ ± _EPSILON 简单判定；多指标显著性
  检验/置信区间在 subgroup n 与小样本标记层面如实暴露，未做
  参数检验——U14 未知阈值一律存为 blocker，不代填。
- contamination 检：标签值命中 prompt 文本 + final 套件跨兄弟
  release 复用；更深层的近邻/嵌入级泄漏检测留待 U15+。
- canary/rollback 请求路径复用 CS-0802 指针机器（promotion 校验
  前置——promote 必过本门，rollback 本身按 known-good 语义不
  要 re-eval）。
- RL/P09（CS-0901，依赖本票）与 CS-0506（U16）明确未做。
