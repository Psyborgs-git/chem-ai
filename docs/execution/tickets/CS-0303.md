# CS-0303 — Implement scoped retrieval and source rights

**Status:** completed
**Phase:** P03 · **Owner:** retrieval

## Changed files

- `workers/ingestion/indexing/` — deterministic chunker:
  `chunk_records` produces `ChunkDraft`s carrying the exact source
  locator (with `slice` markers for >4 kB text), verbatim
  `original_text`, whitespace/lowercase `normalized_text`, and
  `CHUNKING_VERSION = "chunk-v1"` — chunking version is part of
  index identity.
- `services/studio-api/src/studio/persistence/models.py` —
  `SourceChunk` (scoped composite FKs to artifact/batch/record;
  locator + original/normalized text + extraction method +
  uncertainty + chunking version + inherited `rights` JSONB +
  `acl_scope` + `eval_allowed` + `active|superseded|revoked`),
  `RetrievalManifest` (per-search audit: principal, query, kind,
  cache key, source-index version, policy version, eval context,
  returned chunk ids, cached flag), `RetrievalCache` (keyed by
  workspace + cache key).
- `services/studio-api/migrations/versions/0010_retrieval.py` —
  same shape + a GIN FTS index on
  `to_tsvector('english', normalized_text)`.
- `services/studio-api/src/studio/domain/evidence/retrieval.py` —
  `RetrievalService`:
  - `index_batch` — chunks a parsed batch's records; a
    `rights.retrieval == "denied"` artifact is *recorded but not
    indexed* (§9.4); `retention.eval_restricted` sets
    `eval_allowed = false`; same chunking version reindex is
    idempotent.
  - `search` — gate order: any `read_project` grant → PostgreSQL
    FTS (`tsvector`/`plainto_tsquery`, ranked) → `status == active`
    → retrieval-denied rights excluded (JSONB) → `eval_context`
    drops `eval_allowed = false` chunks → `acl_scope` filter via
    the principal's scope-granted `read_project`s → a Python
    post-filter re-checking every row (defense in depth) →
    `RetrievalCache` write + `RetrievalManifest` record. Cache key
    hashes workspace, principal grants, query, source-index
    version (active-chunk count + max `updated_at`), and
    `POLICY_VERSION` — revocation/supersession changes the index
    version so stale exposure can never be served.
  - `revoke_artifact` — all chunks leave the index; manifests
    remain as the audit trail.

## Honest status / boundaries

- Lexical-only by design — embeddings are a *later optional*
  behind the same interface, only with an evaluated benefit; no
  embedding or cloud call exists.
- Retrieval has no GraphQL/REST surface yet — it is service-level
  (a search endpoint arrives when a consumer needs it).
- `eval_restricted` travels in `artifact.retention` pending a
  dedicated eval-suite model (P05).
- Cache invalidation is structural (index-version keying), not a
  sweeper job — revoked content can't be served, stale rows are
  just dead storage.
