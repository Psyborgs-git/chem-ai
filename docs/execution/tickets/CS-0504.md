## 实现内容

### 1. 任务报告 `domain/tasks/report.py`（新）

`task_report(task_id)` 派生报告 —— 非权威状态，不改动任何
不可变记录：

- `contract`：冻结合同摘要（revision id + required metrics +
  hard constraints 计数）。
- `evaluation`：复用 CS-0503 评估器输出（metrics/gates/findings
  快照）。
- `measurements`：accepted/superseded/rejected 计数 + 证据 id 列表。
- `decisions`：`TaskDecision` 历史（closure/state_change 等），
  含每条 closure 的绑定包摘要。
- `scope`：`lab.reviewed`/`lab.planned`/`none`。
- `limitations` + `unknowns`：match_reference 显式标注
  "functional match says nothing about composition or identity"；
  fixture-only / not_validated 明示。
- `claims`：ClaimLink 谱系（supports/contradicts 计数 + ids）。

### 2. 会话清单扩展 `domain/memory/service.py`

`collect_items` 新增 `experiment_outcome` 条目：workspace 内
`status ∈ {stopped, completed}` 且 `deviations|observations`
非空的 `LabExecution` → 失败/异常实验结果进入下一研究会话的
编译上下文（AT-0504-3）。`jsonb_array_length` 判定 JSONB 非空。

### 3. GraphQL

- Query：`taskReport(taskId: ID!): JSON!`（读能力门内）。
- `taskDecisions` 复用既有字段（`Decision` 节点早已存在，
  未重复定义）。
- `packages/contracts/schema.graphql` 重新导出同步。

### 4. 前端 `features/tasks/report/`

- `TaskReportPanel`：合同摘要、评估快照、测量统计、决策历史、
  claim 谱系、limitations/unknowns；页头明示
  "report 是派生导航视图 — 权威记录仍是各域对象"。
- `DecisionsPanel`：替换原 "unavailable-capability" 占位 ——
  列出真实 `TaskDecision`（类别/决策/评审者/包摘要）。
- TaskWorkspace 增加 "report" tab；"decisions" tab 由占位
  改为真实面板。

### 5. e2e `tests/e2e/at-0504.spec.ts`（3 旅程）

- **AT-0504-1 improve**：冻结合同 A → 全链 close
  `supported_success` → 新合同 revision B 冻结后
  `taskDecisions` 中 closure 仍绑定 revision A，签名包不被改写；
  新研究会话 manifest 含 closure 决策条目。
- **AT-0504-2 match_reference**：`compositionKnowledge: "unknown"`
  参考品 → functional 合同（required 功能度量 + optional 分析
  度量）→ 功能度量 met 关闭 → 报告显示功能 met、optional
  inconclusive、composition/identity limitation；页面断言**不存在**
  "same molecule / exact identity / recipe recovered" 类文本。
- **AT-0504-3 discover**：执行记录 observations + deviation 后
  `stopped` → `sessionStart` → manifest 含
  `experiment_outcome` 条目携带失败原因；UI research tab 渲染
  `data-kind=experiment_outcome`。

## 已知限制 / 能力声明

- 三条旅程全部使用合成 fixture 数据 —— 证明软件工作流，
  不主张科学有效性（§25）。
- match 旅程的 functional 范围不推断配方/身份；成分恢复是
  独立研究假设（§11.3），UI 已负向断言。
- 报告为派生视图；权威状态仍属各域记录（contract/candidate/
  measurement/decision），报告字段变更不产生审计事件。
- `experiment_outcome` 条目仅从 executions 的
  deviations/observations 提取；无 observation 的失败运行
  不产生条目（后续可加 run-level 结果摘要）。
- 优化、定向科学、微调、RL、云阶段仍未实现 ——
  依赖门控保持不变。
