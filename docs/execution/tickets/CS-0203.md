# CS-0203 — Implement material, grade, lot and reference registry

**Status:** completed
**Phase:** P02 · **Owner:** controller

## Changed files

- `services/studio-api/src/studio/persistence/models.py` —
  six new workspace-scoped tables:
  - `MaterialIdentity` — kind
    (`defined_molecule|polymer|commercial_mixture|substance_class|unknown`),
    identifiers *with their sources*, optional structure +
    `structure_format` + `structure_status`
    (`none|unreviewed|reviewed`), aliases, confidentiality,
    evidence status.
  - `IdentityMatch` — proposed equivalence between identities;
    `proposed|accepted|rejected`, confidence, proposer provenance,
    reviewer fields. A registry match is a proposal until reviewed.
  - `MaterialGrade` — material + supplier + trade name; active
    content as a basis-required Quantity DTO; `reconciled_into`
    (the only merge pointer — never silently set).
  - `MaterialLot` — grade + lot number, dates, certificate
    artifact ids (bytes stay in the vault).
  - `ReferenceProduct` + `ReferenceProductRevision` —
    `composition_knowledge` (`known|partial|unknown`), claimed vs
    measured properties in revision payloads, revisions frozen by
    the same immutable-revision trigger as contracts.
- `services/studio-api/migrations/versions/0006_materials_registry.py`
  — same shape in SQL; attaches `cs_revision_guard('product_id')`
  to reference revisions.
- `services/studio-api/src/studio/domain/materials/service.py` —
  `MaterialService`: `create_identity` (entered structures are
  *unreviewed*), `review_structure` (human `review_science` only),
  `require_structure` — the gate structure-required tools call,
  returning `MISSING_IDENTITY` unless the structure is reviewed;
  `propose_match`/`review_match` (proposal → human review, agents
  cannot review); `create_grade` (validates active-content DTO
  basis), `find_shared_identifier_grades` (dedup *report*, never a
  merge), `reconcile_grades` (human review + reason, the only merge
  path); `create_lot`; `create_reference_product`,
  `draft_reference_revision` (rejects an ingredient list when
  composition knowledge is `unknown`), `freeze_reference_revision`
  (supersede via the trigger's only legal transition),
  `reference_composition` (returns `None` for unknown — no invented
  list).
- `services/studio-api/src/studio/api/graphql/types.py` — Relay
  nodes `MaterialIdentity`, `MaterialGrade`, `ReferenceProduct`,
  `ReferenceProductRevision` (scoped `_by_ids` resolution).
- `services/studio-api/src/studio/api/graphql/schema.py` —
  `materials` mutation namespace: `identityCreate`,
  `structureReview`, `matchPropose`, `matchReview`, `gradeCreate`,
  `gradeReconcile`, `referenceProductCreate`,
  `referenceRevisionDraft`, `referenceRevisionFreeze` — all typed
  error payloads, idempotent variants where they create records;
  shared `_mutate` helper factors the idempotency/commit boilerplate.
- `apps/studio-web/src/features/materials/operations.ts` — the nine
  Relay operations through the single network layer (boundary-
  checked); `index.ts` barrel.
- `packages/contracts/schema.graphql` — re-exported.
- `services/studio-api/tests/integration/test_materials_registry.py`
  — 12 integration/security tests.

## Acceptance mapping

- **AT-0203-1** (purchased reference with no recipe → composition
  stays unknown, no invented ingredient list):
  `test_unknown_reference_saves_and_reads_as_unknown` (create +
  read → `composition_knowledge == "unknown"`,
  `reference_composition() is None`);
  `test_revision_with_unknown_composition_rejects_ingredients`
  (`VALIDATION` when a payload claims `unknown` *and* carries a
  composition list; honest `composition: null` accepted and the
  frozen revision still reads `None`);
  `test_known_composition_records_and_reads` proves the known path
  works end-to-end.
- **AT-0203-2** (two grades sharing a chemical identifier → dedup
  keeps distinct until reviewed reconciliation):
  `test_shared_identifier_report_keeps_distinct` — both grades with
  CAS 9004-82-4 appear in one report group, both rows persist
  unreconciled; `test_reviewed_reconciliation_resolves_group` —
  `review_science` + reason marks `reconciled_into`, group resolves;
  `test_reconciliation_requires_review_and_reason` — steward and
  agent denied (`FORBIDDEN`), reviewer without reason denied
  (`VALIDATION`).
- **AT-0203-3** (unreviewed identity match + structure-required
  tool → missing identity reported):
  `test_unknown_identity_has_no_structure`,
  `test_proposed_match_does_not_unblock_structure` (a proposed
  match — and even an *accepted* one — never fabricates a structure
  on the source; the candidate's own unreviewed structure is also
  blocked with `structureStatus: "unreviewed"`),
  `test_reviewed_structure_passes` (only `review_science` review
  unblocks; agents denied), `test_match_review_human_only`.

  outbox/audit in-transaction
- fixture: none
- blocked: none for this ticket's scope

## Limitations

- `require_structure` is the service-layer gate; the actual
  structure-required *tools* (calculators, predictors) arrive with
  the engine-adapter tickets — they call this before any request.
- `find_shared_identifier_grades` reports exact scheme+value
  matches only; near-duplicate *grouping* (fuzzy names, alias
  overlap) is a separate operation per §6.2 and lands with the
  review-workflow UI.
- `materialLot` has a service path but no GraphQL mutation yet —
  lot recording UI arrives with task-workspace screens (CS-0206).
- Match proposals store `proposed_by` provenance but there's no
  notification/queue surfacing them yet.
