## 实现内容（按 ticket 顺序）

### 1. `packages/engine-adapters/elabftw/engine_adapter_elabftw/`（~700 行）

遵循 engine-adapter 惯例的**可选、显式、默认关闭**桥接器，不被 API
导入——缺配置对启动/健康检查/其余测试完全不可见：

- `contracts.py` — 诚实状态枚举与链接模型：`CONFIG_STATES`
  (`not_configured` / `configured_disabled` / `enabled`)、`LINK_STATES`
  (`synced` / `review_required` / `stale`)；`ElnConfig`（frozen
  dataclass，`STUDIO_ELN_BASE_URL` / `STUDIO_ELN_API_TOKEN` /
  `STUDIO_ELN_ENABLED` / `STUDIO_ELN_TIMEOUT_SECONDS` /
  `STUDIO_ELN_VERIFY_TLS`；`enabled` 缺 URL+token 不会成立——
  `ENABLED=1` 单独不足以构成连接）；`ElnEntityRecord`（pydantic，
  eLabFTW API v2 字段，unknown 字段 `extra="ignore"` 向前兼容），
  `remote_fingerprint()` = `{title, body, metadata, status, category,
  state}` 的 sha256；`ElnLink`（local_ref + entity 引用 +
  `remote_version`(modified_at) + `remote_sha256` + 导入快照 +
  review 记录）；`ImportVerdict` / `ExportResult` dataclass。
- `transport.py` — 全部网络 I/O 的唯一容器：`ElnTransport`
  Protocol；`HttpElnTransport`（stdlib urllib，`Authorization:
  <key>`，`/api/v2` 前缀，HTTPError→`ELN_BAD_RESPONSE`、
  URLError/timeout→`ELN_UNREACHABLE`）——仅当 state==`enabled` 才能
  构造，惰性创建，`capability()` 永不触网；`FixtureElnTransport`
  （录制实体字典、`calls` 日志、`go_offline()`/`mutate_entity()`，
  kind=`fixture`）。
- `mapping.py` — `load_fixture()`（适配器自带 `tests/fixtures/`）、
  `entity_to_record()`（v2 JSON→record，畸形→`ELN_BAD_RESPONSE`）、
  `to_export_payload()`（在 `metadata.extra_fields.studio_provenance`
  嵌入 source_system / adapter_version / local_ref / local_revision /
  `sync_direction: "export-only; no bidirectional sync"`）。
- `adapter.py` — `ElabftwAdapter`：`capability()`（状态面——
  account 恒 None、token_present 布尔、connectivity 恒
  `not_probed`、scientific_status 恒 `not_validated`）；
  `import_entity(selector)` → `imported`(新链基线) /
  `unchanged`(同时清 stale 或已回转的 review) /
  `review_required`(漂移：记录基线 vs 实测 version+sha+incoming
  快照，**基线绝不覆写**) / `unavailable`(标 stale，本地快照保留)；
  `export_record(local)` → `exported`(POST) / `updated`(先重读远端，
  漂移则 `review_required` 拒绝 PATCH，干净才 PATCH) /
  `unavailable`；`link_status(link_id)`（对任何配置/断连状态均不
  抛错——local_evidence=intact/corrupted，remote∈
  not_configured/disabled/unavailable/error/available，漂移检查同
  上）；`resolve_review(link_id, action)`：
  `accept_remote`=**实时**重取并采纳所见；`keep_local`=保留基线且
  不压制后续漂移检测；`export_state()` 序列化链路注册表。
- 错误一律 typed JSON `{code, message}`：`ELN_NOT_CONFIGURED` /
  `ELN_DISABLED` / `ELN_UNREACHABLE` / `ELN_BAD_RESPONSE` /
  `ELN_INVALID_INPUT`。

## 已知限制 / 能力声明

- **能力标签：`fixture`（适配器）+ live `not_configured`/`deferred`**：
  fixture 全绿 ≠ live 集成；本发布**从未发起**任何真实 eLabFTW 调用，
  HttpElnTransport 为真实代码但无任何测试对其验证（如实标注
  unverified）。live 化需 (a) owner 置备实例 URL+凭据入 secret、
  (b) 独立的 ownership/同步方向/冲突决策、(c) `STUDIO_ELN_ENABLED=1`、
  (d) 对真实实例的实测——按 U16 决定。
- **链路无 DB 持久层**：`ElnLink` 注册表在内存，`export_state()`
  供调用方序列化落库——域侧持久化归后续 ticket。
- **无 connector UI**：`apps/studio-web` 无 `/settings` 路由/集成设置
  面（既有缺陷，已如实记录）；AT-0506-3 由 `capability()`/`ElnConfig`
  状态面满足——未来 UI 必须原样渲染该面。
- **范围外**：uploads 附件传输、webhooks、批量导入、双向同步
  （永不实现 by design）。
