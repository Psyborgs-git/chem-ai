# CS-0403 — Build isolated execution, cancellation and run cache

**Status:** completed
**Phase:** P04 · **Owner:** security

## Changed files

- `workers/common/executor.py` — two backends behind one contract:
  - `ContainerBackend` (preferred): `docker run --network none
    --read-only --cap-drop ALL --security-opt no-new-privileges
    --user 65534 --tmpfs /tmp:rw,noexec,nosuid --memory/--pids-limit`,
    only the per-run scratch bind-mounted; `docker kill` + `rm -f`
    destroys the whole tree.
  - `SubprocessBackend` (fallback): argv-only (never a shell),
    scrubbed env (HOME/TMPDIR → scratch, no inherited credentials
    or proxies), per-run scratch, POSIX rlimits applied
    per-capability — each limit is *probed* first and the applied
    set is recorded (macOS refuses RLIMIT_AS here → reported, not
    claimed; RLIMIT_NPROC is excluded deliberately — it bounds the
    UID, not one tree), and process-group kill
    (start_new_session + SIGTERM→SIGKILL on the pgid).
  - `IsolationProfile.enforced` records exactly which controls
    fired per run; `ExecResult` carries the profile, scratch
    dir/files, wall time, truncation, and `tree_exited`.
- `workers/common/cache.py` — `build_context` (canonical input,
  chemical/context representation, engine/adapter versions,
  method, parameters, precision, seed, policy version, scope) and
  `cache_key` (sha256 over canonical JSON).
- `services/studio-api/src/studio/domain/runs/cache.py` +
  `models.py` + `migrations/versions/0015_run_cache.py` —
  `RunCacheEntry`: workspace-scoped, unique key, insert-only
  (`put` returns the existing row on conflict — idempotent),
  `invalidate` marks rather than deletes, `get` never serves an
  invalidated entry.
- `services/studio-api/src/studio/domain/runs/execution.py` —
  `AttemptExecutor`: admits → accepts → starts → runs in the
  backend → maps outcome to run semantics. exit 0 WITHOUT a
  parseable structured result is `failed`, never success (§7.3);
  cancellation calls `confirm_cancelled` + releases the
  reservation in the same transaction; timeout → `timed_out`.
- `infra/local/worker-profiles/` — `restricted.json` (container
  profile), `development-reduced.json` (subprocess profile with
  `network_denied: false` stated), README documenting what each
  enforces.
- `services/studio-api/tests/unit/test_run_cache.py`,
  `tests/integration/test_isolated_execution.py`,
  `tests/security/test_isolation_profile.py`.

## Honest status / boundaries

- `sandbox-exec` exists on this host but aborts on any invocation
  (verified) — it is not a viable enforcer here, so the subprocess
  profile cannot deny network egress and says so. The container
  profile is the only one that enforces it; a run requiring
  network denial under the subprocess profile must be blocked by
  policy (§13.3) — the `AttemptExecutor` already refuses a
  profile missing `argv_only_no_shell`.
- macOS refuses `RLIMIT_AS` and `RLIMIT_NPROC` cannot bound one
  tree — both are reported in `profile.enforced["rlimits"]`
  rather than claimed. The watchdog relies on wall-time + kill.
- Cache `put`/`get`/`invalidate` exist; no executor populates the
  cache yet — that wiring lands with the first real engine
  adapter (CS-0404+).
- Partial outputs are reconciled as failure states, never
  promoted (`no_result`/`exit_*` failures; scratch files are
  listed for inspection).
