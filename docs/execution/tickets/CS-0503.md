- **外部输入**: 无（合成实现）

## 实现内容

### 1. 度量归因 `§12.3`

- 迁移 `0019_measurement_metric`：`measurements.metric`
  **nullable** — 未归因读数保持诚实，永远不能计入合同度量。
- `LabMeasurementService.record_measurement` 接受 `metric`；
  GraphQL `MeasurementRecordInput.metric` + `Measurement.metric`
  字段透出；前端录入表单可填归因，测量行显示
  `metric: <id>` / `unattributed` 徽章。

### 2. 共享单位模块 `domain/lab/units.py`

- 从 `measurements.py` 抽出单位/换算/比较逻辑为单一权威模块 —
  测量合同比较与评估器共用同一白名单换算表，不发散。
  （viscosity/fraction/mass/volume/time/absolute-temperature；
  质量↔体积无密度不换算。）

### 3. 门优先评估器 `domain/tasks/evaluation.py`

`TaskEvaluationService.evaluate(task_id)`：

- 加载任务 + **冻结**合同（非冻结/缺失 → 不可评估报告）。
- `assess_metric(metric, rows)` 为**纯函数**（无 DB）：
  逐条检查 accepted+applicable+metric 归因的测量 —
  missing/censored/非数值/无单位/单位不兼容/无白名单换算 →
  各项 `inconclusive` + 带 `action` 的 finding，**绝不强制
  pass/fail**。支持 `fixture-single-value|single|min|max|mean`
  聚合；`replication_rule.minIndependentBatches` 以批次数核算
  （同一样品重复读数不膨胀 — 与 CS-0502 口径一致）；
  `required_evidence` 中非 `lab_measurement` 的类别 →
  `evidence_class_missing` inconclusive。
- 硬约束独立评估（`hard_constraints[].check`）：
  `kind=="metric"` 复用度量评估；`kind=="ingredient_absent"`
  解析 bound candidate → `entity_revision_id` →
  FormulationRevision.payload.ingredients 判定；
  未知 check → `not_evaluated`（计为 unproven gate）。
- 汇总：**gate fail 或 required metric miss →
  `supported_failure`**；全部 required met 且所有 gate pass →
  `supported_success`（且须至少一个 required metric — 空合同
  不能证明成功）；其余 → `inconclusive`。
- 报告字段：`assessable`、`metrics[]`（verdict/evidenceIds/
  findings/comparedAgainst/independentBatches）、`gates[]`、
  `unknowns[]`、`evidenceIds`、`supportedSuccessEligible`、
  `suggestedDecision`、`fixtureOnly: true`。

### 4. 关闭包与复核 `§7.1, §12.3`

- `closeout_packet`：绑定 contractRevisionId、
  candidateRevisionId（最近 research-accepted 候选）、
  metrics/gates/evidenceIds 快照、`suggestedDecision`、
  `fixtureOnly` + `scientificValidation: "not_validated"`。
- `TaskService.close` **服务端推导**关闭包 —— 客户端传入的
  packet 仅作为 `reviewerPacket` 附档，绝不成为绑定的证据
  记录。`supported_success` 经由 `_success_evidence_gate`
  （同一评估报告）校验 — 任一 required 未 met / gate 未 pass /
  无冻结合同 → `EVIDENCE_INSUFFICIENT` + safe_details
  （unmet/unprovenGates/suggestedDecision）。
- 关闭仍是 **human-only**：`principal_kind != "user"` →
  FORBIDDEN（评估器资格不改变）。
- `reassessment_status`：最近 closure decision 的
  `packet.evidenceIds` 中如有测量已 `superseded|rejected`（或
  消失）→ `needsReassessment: true` + stale 清单 — **签名包
  不被改写**。

### 5. GraphQL

- Query：`taskEvaluation(taskId)`、`taskCloseoutPacket(taskId)`、
  `taskReassessmentStatus(taskId)`（均 JSON，读能力门内）。
- `Measurement.metric` 字段 + `MeasurementRecordInput.metric`。

### 6. 前端 `features/tasks/closeout/`

- `CloseoutPanel` 挂为 TaskWorkspace 新 "closeout" tab：
  - 建议决策徽章 + `fixture-only — not scientific validation` +
    cycle；明示"评估器只建议 — 关闭永远是人类审查者决定"。
  - reassessment 横幅（签名包证据被 superseded 时）。
  - metrics 表（label/verdict 徽章/comparedAgainst/证据数/
    findings）、gates 表（"never compensated by performance"）、
    unknowns 列表。
  - `active` 状态提供 "send to review" 转换按钮；
    `awaiting_review` 显示关闭表单：decision 下拉
    （`supported_success` 在未 eligible 时禁用并标注）、
    评审理由、**人类确认复选框**（不勾选按钮禁用）；
    `closed` 显示不可变包说明。

## 已知限制 / 能力声明

- 评估器仅覆盖 `check.kind ∈ {metric, ingredient_absent}` 的硬约束；
  未知 check 计为 `not_evaluated`（即 unproven → 阻断
  supported_success，诚实偏保守）。
- `replication_rule` 仅识别 `minIndependentBatches` 字典形；
  fixture 的字符串形 `"n>=3"` 不解析（不因未识别而放宽 —
  其余条件仍需满足）。
- 聚合仅 `fixture-single-value|single|min|max|mean`；未知聚合 →
  inconclusive。
- `taskClose` 输入仍接受 `packet`（向后兼容）但服务端总是存储
  evaluator 推导包 — 客户端值不会成为绑定记录。
- 关闭需要 `awaiting_review`；UI 提供单步 "send to review"，
  更早状态的合法转换链不在本面板内。
- 软件验收 ≠ 科学验证：packet 显式标注 `fixtureOnly` +
  `scientificValidation: not_validated`。
