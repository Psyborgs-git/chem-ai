## 实现内容

### 1. `packages/engine-adapters/qcengine/` — 钉版适配器（不进核心科学依赖）

- `contracts.py`：纯 pydantic 契约，**无任何科学包 import**——核心服务
  不依赖 qcengine/qcelemental/xtb。`QCENGINE_VERSION=0.51.0`、
  `QCELEMENTAL_VERSION=0.51.2`、`ADAPTER_VERSION=qcengine-adapter/v1`、
  `TESTED_PROGRAM_VERSIONS={xtb:"22.1", psi4:"1.10.2"}`。
- 显式支持矩阵（§16.2 最小集合，逐驱动声明）：
  - `xtb`：`GFN0/GFN1/GFN2-xTB`、`GFN-FF`（energy+gradient）、
    `IPEA-xTB`（energy-only）；keywords 白名单 `{solvent, accuracy,
    max_iterations}`；solvent 白名单为 xtb ALPB 集合（13 项，小写规范化）。
  - `psi4`：`hf`、`b3lyp`（energy+gradient），bases
    `{sto-3g, def2-svp, cc-pvdz}`；无其他 keywords。
  - method 大小写规范化；未知 method/driver/basis/keyword/solvent →
    `ENGINE_UNSUPPORTED_INPUT`，**绝不替换猜测值**。
- `QuantumJobSpec`：`extra="forbid"`，分子须显式给出
  `symbols/units/charge/multiplicity/geometry` + `provenance{kind,source}`；
  `ResourceEnvelope{wall_seconds≥1, memory_mebibytes≥32, ncores 1-32}`；
  总原子数 ≤200；`spec.digest()` 内容寻址。
- `validation.py`：118 元素表；几何必须 flat 3N、有限、≤1e5 bohr、
  无重合原子（<1e-12 bohr²）；`electrons=ΣZ−charge>0` 且
  `(electrons−(multiplicity−1))` 为偶（自旋/电荷宇称）——
  三态水是合法的（O₂ 基态即三重态），双态水被拒。
- `build_atomic_input`：构造 QCSchema v1 `AtomicInput`（几何转 bohr、
  molecule provenance 带 PEP 440 version、`protocols.stdout=True`、
  `extras.studio` 携带 adapter_version + geometry_provenance）。
- `classify_result`：`success!=True`→`engine_failure`；energy driver
  要求有限非 bool `properties.return_energy`，gradient driver 要求
  `return_result` 为有限向量（容忍 ndarray）；否则
  `malformed_result`——**exit-0 + 畸形/未收敛输出不算科学可用**。
- `adapter.py`：`QCEngineAdapter.capability()` 报告
  `available_tested`/`installed_unverified`/`not_installed`（dist
  metadata 版本，非 `xtb.__version__` 陈旧的 "20.2"）；
  `compute()` 校验容器内 qcengine/qcelemental 版本钉扎、persisted
  payload 与 spec 漂移检查（`AtomicInput.parse_obj` + 归一化比对）、
  `qcengine.compute(raise_error=False)` → `FailedOperation` 映射
  `engine_failure`（保留 `error_message`），非 AtomicResult →
  `malformed_result`；原始 stdout/stderr 截断保存（64KiB 上限）。

### 2. `workers/chemistry/quantum/` — 隔离运行器（镜像 `workers/optimization/`）

- `Dockerfile`：`mambaorg/micromamba:2-debian12-slim` 基座（xtb 只在
  conda-forge 发行），`python=3.12 xtb=6.7.1 xtb-python=22.1` +
  `requirements.lock` 冻结 pip 层（qcengine 0.51.0 / qcelemental
  0.51.2 / pydantic 2.13.5 …）。psi4 刻意缺席 → `not_installed`。
- `runner.py`：读 ≤2MB `request.json{spec,input}` → 落盘
  `input.qcschema.json` + `result.json` → stdout 仅 JSON；
  `--capability` 探针模式；`EngineFailure`/`MemoryError` →
  `{code,message}` + exit 2；其余异常 → 脱敏 `ENGINE_UNSUPPORTED_INPUT`
  （不泄漏专有 traceback）。
- `runtime.py`：`IsolatedQuantum.compute` 经 `ContainerBackend`：
  `--network none`、只读根、UID 65534、`cap-drop ALL`、
  no-new-privileges、tmpfs /tmp、scratch `chmod 0777`、
  `ExecLimits{wall=cpu=spec.resources.wall_seconds, memory, pids=64,
  output=2MB, files=64MB}`；cancel → `RUN_CANCELLED`、超时 →
  `RUN_TIMEOUT`、非零退出/无输出 → `ENGINE_UNAVAILABLE` 或容器内
  JSON `{code}`；`available()`/`capability()` = 镜像存在 + 容器内探针。

### 3. 服务端接线 `domain/chemistry/quantum.py` + `api/capabilities.py`

- `QuantumService.request`：profile 关 → `ENGINE_UNAVAILABLE`；
  spec 校验/EngineFailure → run 以 `blocked(reason="insufficient_inputs",
  detail={capability, detail, policy})` 落库——**聚合物缺参即 blocked，
  不发明替代分子，零 artifact/attempt**。
- 合法请求：**QCSchema 字节先持久化**（vault 私有路径，
  `source_kind="derived"`, `upload_state="committed"`）再建 run；
  引擎镜像缺席 → `blocked("engine_not_installed")`；admission 按
  spec 资源包络准入（queue `quantum`）。
- `execute`：从 vault 取回 persisted payload → 重建 spec →
  isolated compute → 结果 artifact 持久化 → `usable` 才
  `complete_attempt`；`malformed_result`/`engine_failure` →
  `fail_attempt(retryable=False)`；cancel/timeout 如实映射。
- `capabilities.py`：quantum profile 用真实容器探针替换占位符；
  新增 `engines.qcengine` 块（available/degraded/unavailable +
  逐 program 状态明细）。

  **reference**: documented −5.070451354848316 Eh，observed

  （结构/电荷/自旋/宇称、元素表、3N、非有限/重合、方法/驱动/基组/
  关键字白名单、聚合物组合缺参拒绝、分类器矩阵、缺失镜像时
  unavailable —— 镜像在则显式 skip）。
- `tests/engines/quantum/test_qcengine.py`：9 个 `engine` 标记测试，

## 已知限制 / 能力声明

- **capability 标注**（§16.1）：xtb = `available_tested`（本票据实测）；
  psi4 = `not_installed`（镜像刻意不含）；镜像缺席 = `engine_not_installed`
  blocked；输入缺参 = `insufficient_inputs` blocked；
  `scientific_status` 恒为 `not_validated`——fixture/参考计算仅证明
  **安装可用性**，不构成科学验证。
- 参考容差是 method/version 专属（GFN2-xTB @ xtb 22.1，1e-3 Eh）；
  未发明产品级阈值。
- xtb 对超参数化元素（Z>86）**SIGSEGV 而非优雅报错**——容器死亡
  如实上报 `ENGINE_UNAVAILABLE`，绝不报部分成功；这是上游
  xtb-python 限制，隔离层兜底。
- U：multiplicity 5 的 U 原子在 spec 层合法（宇称满足）——失败
  发生在引擎内，正是 AT-0701-2 的覆盖点。
- 原生 host `quantum` extra 仅提供 qcengine/qcelemental；xtb/psi4 二进制
  始终来自钉版容器——宿主能力标签不受影响。
- `make test-e2e`、训练/RL 超出范围（P08+ 禁止）。
