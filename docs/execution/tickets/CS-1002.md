## 实现内容

### 1. `domain/learning/exports/transform.py` — 变换流水线（~1330 行）

- **最小选择**（§20.3 步骤 1）：payload 只含冻结快照 manifest 中
  允许的记录，且每条记录按类型走**允许列表字段**——
  measurement `{metric(aliased),method,valueType,value,conditions}`、
  claim `{sourceClass,labelKind,subject,statement,conditions}`、
  session `{messages[{role,content}]}`；其余字段进 `removedFields`
  报表（reviewable）。manifest 中被排除的记录（`excluded`）按
  `exclusionReason` 透传；claim 来源 artifact 的 `rights.export`
  非 allowed/owned → 整条拒绝并记 `export_rights_unresolved`；
  未知 kind → `unsupported_kind`。完全相同的两条变换后记录合并
  去重（`mergedDuplicates` 计数）。
- **LOCAL-only 别名映射**（步骤 2）：工作区内
  MaterialIdentity 名称/标识符/别名、MaterialGrade 供应商与牌号、
  FormulationFamily 名、LabBatch/LabSample 标签、Artifact
  original_name、Principal login/display_name、metric 名 →
  确定性 token（`mat-0001`/`a-0001`/`m-0001`/`lab-`/`p-`/`f-` 前缀，
  最长匹配先替换）。映射表落在 `local_alias_map` JSONB 列——
  **绝不进入 payload、digest 或任何 API 响应**（view 只给
  `{count,kinds,localOnly:true}` 摘要）。
- **metadata 剥离**：递归 denylist——常见 metadata 键全集 +
  `_id/_by/_at/_key/_ref/_name/_label/_path/_file/_url/_uri/_email/
  _note/_hash/_digest/_token/_secret/_login` 后缀；剥除的每个键
  记 `removedKeys{ref,path,key,reason}`（reviewable，绝不静默丢）。
- **残留披露扫描**：对保留值递归扫描——URL/文件路径/UUID/
  hash blob（medium，flag 保留供审）与 email/secret 值（high，
  **就地 redact** 为 `[redacted:…]` 并 flag）；process_windows
  （temperature/rpm/duration 等键集合）、ratios（wt%/ppm/组成
  合计 ≈100% 或 ≈1 的字段组）、structures（InChI/SMILES 形）、
  derived_features（spectra/peaks/descriptors/embeddings 键）、
  outcomes（测量值本身）、free_text、metadata 七类 residual 全部
  列入 `residual_report`。verdict 恒 `residual_disclosure`，
  **anonymous/safe/certified 恒 false**，advisory 直述
  "Masking is not confidentiality…"（§20.3 诚实语言——
  scanner 只能 flag，绝不能证明商业秘密已除尽）。
- **§20.2 manifest + digest 绑定**：`manifest{version,
  transformationVersion, proposalId, proposalBoundDigest,
  snapshot{id,digest,purpose}, payload{digest,recordCount,byteSize,
  fields}, reports{redactionDigest,residualDigest}, classification,
  recipient{provider,account,region}, environment{containerDigest:None,
  runtime{python,transform}}, permittedJob{operation,runKind,runId},
  limits{maxRecords,maxBytes}, retention{expectation,
  deletionExpectation}, expiry, approver:None, egress:"deny"}`；
  `bound_inputs` = manifestVersion + proposalBoundDigest +
  snapshotDigest + payloadDigest + transformationVersion +
  classification + recipient + permittedJob + limits + expiry →
  `bound_digest`（`bound_inputs` canonical sha256）——**批准绑定
  精确 payload+transformation digest**；`transformation_version`
  或分类复审变更即失效（AT-1002-3）。同 digest 重复 prepare 复用
  同一行（幂等）。
- **服务**：`TransformService`——`prepare`（`CAP_REVIEW_EXPORT` +
  提案 open + `datasets.get`（CAP_READ_PROJECT）+ frozen +
  `drift_status` 复检 + task 匹配 + 有界校验）→ 持久化
  `ExportTransformedPayload` + 审计 `export.transform_prepared`；
  `decide`（`grant(action="export", bound_inputs=row.bound_inputs)`——
  账本侧强制 `CAP_APPROVE_EXPORT`，agent principal 在
  `effective_grants` 层被剥离 → 永不能批准）+ 提案 status 更新 +
  审计 `export.decided`；`validate_approval`（`require_valid` →
  无批准 FORBIDDEN / 最新批准 digest 不匹配 APPROVAL_STALE /
  revoked FORBIDDEN / expired APPROVAL_EXPIRED——CS-1003 消费的
  校验钩子）；`set_classification`（CAP_REVIEW_EXPORT + 必填
  rationale + 记录 `classification_review{from,to,rationale,
  reviewedBy,at}` 并**重建 bound_inputs/bound_digest**——分类
  复审变更同样失效已存批准）；`latest_payload`（服务端 `seq`
  序列排序——created_at 同事务内并列不可靠）；`review_view`
  （CAP_REVIEW_EXPORT + exact payload 文档 + reports + manifest +
  approval state（none/rejected/stale/revoked/expired/approved 镜像
  require_valid 语义且按 proposalBoundDigest 隔离防串案）+
  snapshot 选项 + cloud_capability + `capabilities{canReview,
  canApprove}`（`ctx.has` 服务端判定）+ egress:"deny"）。
- **有界输入**：max_records ≤2000、payload ≤4 MiB、声明文本
  ≤120 字符、字符串 ≤20k、list ≤500、嵌套 ≤24 层、alias ≤5000。

## 已知限制 / 能力声明

- **transfers 仍然 inert**：本票只产出 transformed payload +
  manifest/bound_digest + 批准绑定机械；无 broker、无传输、无
  credential——CS-1003 消费 `validate_approval` 与 manifest。
  `environment.containerDigest` 恒 None（本环境无容器镜像可引）。
- **scanner 是 advisory，不是证明**：verdict 恒
  `residual_disclosure`，anonymous/safe/certified 恒 false——
  UI 与报表语言直述 "Masking is not confidentiality…scanner
  flags risk; it cannot certify"（§20.3）。high-severity 模式
  （email/secret 值）就地 redact；medium（URL/path/UUID/hash）
  只 flag 保留——复核者看到的就是将要发送的精确字节。
- **残留识别是启发式**：ratios 由键名/单位/数值合计 ≈100% 或 ≈1
  触发；structures 由 InChI/SMILES 形触发；非组成型 dict 不会误报，
  但新奇编码（图表、表格外的隐性通道）不保证抓到——advisory
  已声明此界限。
- **别名映射 bounded**：工作区 alias 候选 ≤5000、长度 [3,200]；
  超出者原样保留（但其值若无标识语义则无泄露面）。映射只在
  `local_alias_map` 列 + 审计快照外——永不进响应。
- **分类默认 = 来源最大等级**：claim 无 artifact 时按 restricted
  处理；reviewer 复审变更需 CAP_REVIEW_EXPORT + rationale，
  变更即重建 digest（既有批准失效）。classification 无降级捷径。
- **批准面在 proposal 粒度**：多条 payload 行共存时 `latest_payload`
  驱动 view；v1 批准不会误用于 v2。同一 proposal 上 prepare 幂等
  （同 bound_inputs → 同行）。
- **UI 为审查面**：§22.4 状态（loading/error/empty/ready）齐备；
  无批准按钮以外的执行动作——无 "send"、"schedule" 或任何
  egress 控件。
