## 实现内容

### 1. 出站经纪层 `infra/cloud/broker/`（唯一出口，§20.2/§20.5）

- `cloud_broker.types`: `ApprovedBinding` — 批准绑定的**完整快照**：
  manifest digest、payload digest/字段、source digests、
  transformation version、classification、recipient
  (provider/account/region/environment)、runtime digest、
  permitted job、limits (max_bytes/max_artifacts/wall_seconds/
  retention_expectation/deletion_required)、expiry、approver；
  `digest()` = `digest_doc(bound_doc)`，与批准账本 `bound_digest`
  逐字节相等（`canonical_json` 与 studio idempotency 层一致：
  `sort_keys + separators + default=str`）。`Permit`（单次出站许可，
  消费后不可复用）、`AttemptRecord`、`JobLineage`、
  `ReconcileReport`、`DeletionReceipt`、`CallbackEvent`、
  `Recipient`、`TransferLimits`、`TransferOrder`。
- `cloud_broker.providers`: `CloudProvider` Protocol
  （submit/status/cancel/delete/drain_callbacks）；
  `PROVIDERS = {}` — 生产 provider 一律 `ProviderNotConfigured`
  （`status="not_configured"`）；测试注入 in-process `ProviderDouble`
  （实现同一契约，记录 `received_bytes`，支持 `fail_submit`/
  `inject_callback`/`succeed` 故障注入）。
- `cloud_broker.gate`: `EgressGate` — 字节边界唯一放行点；校验
  permit 未消费/未过期/payload digest 匹配/字节上限；`emit()` 先标记
  permit spent 再调用 `provider.submit` — 校验失败**零字节**出站。
- `cloud_broker.broker`: `EgressBroker` — `dry_run`（全量校验不发
  送）/`transfer`（校验 → 发单次 Permit → gate.emit → 记录
  transferred/denied/failed + 初始化 JobLineage；provider 缺失或
  抛错如实记 `failed`，绝不静默）/`cancel` / `reconcile`（排空回调
  + status → ReconcileReport，honest `exposed` +
  `unresolved_retention`）/ `delete`（DeletionReceipt）/
  `revoke_binding`（digest 吊销，后续 transfer 在 binding 校验处
  即被拒）/ `handle_callback`（幂等：callback_id 去重 + 状态秩
  收敛 + 终态不回退 + artifact 并集）/ `seed_lineage`（重启后
  从持久化行恢复 lineage）。每次尝试写入 attempts 台账
  （outcome/reason/bytes_emitted）。
- **重校验时机**（§20.2）：broker 每次 transfer 前重新计算
  `binding.digest()` 与 requested digest/recipient/job/approval
  digest 相等性 —— **digest 相等性，不是字段相似性**；permit
  单次使用阻断重放；过期 binding 直接拒绝。重试只允许同一
  manifest/recipient/expiry/budget 之内（尝试键幂等去重）。

### 2. 服务端 `services/studio-api/.../exports/broker.py`（~800 行）

`ExportBrokerService(db, ctx, *, broker=None, vault=None)`：

- `dry_run(payload_id)` — `CAP_REVIEW_EXPORT` 门 +
  `approvals.require_valid(action="export",
  bound_inputs=row.bound_inputs)` **即时重校验**（§20.2）→
  `broker.dry_run` → 记 `validated`/`denied` attempt + audit。
- `submit(payload_id, *, attempt_key=None, requested_recipient/
  requested_job/requested_digest=None)` — 同上重校验；`_binding()`
  从 `row.manifest`+`row.bound_inputs` 构造 `ApprovedBinding`
  （`bound_doc=row.bound_inputs` → digest ≡ 批准账本 digest）；
  请求参数默认取批准 manifest 原值，任何漂移在 broker 校验处
  拒绝 → `denied`，**零字节**。transfer → 记 attempt（字节数
  如实）→ job.status/external_job_id/bytes/exposed 落库 →
  `export.attempt.<outcome>` outbox 事件 + audit。
- `cancel(job_id)` — `broker.cancel` → `_apply_report` →
  `cancellation` receipt；job.status='cancelled'，external_state
  保留 provider 自报值（诚实）。
- `revoke(payload_id, reason)` — **仅人类主体**（agent 主体
  `forbidden`）；找最新批准 → `approvals.revoke` →
  `broker.revoke_binding(bound_digest)` → 所有 live job
  cancel+reconcile+cancellation receipt；audit `export.revoked`。
  **吊销前已出站的字节仍如实记为 exposed**（AT-1003-2）。
- `reconcile(job_id)` / `delete_remote(job_id)` — report/receipt
  分别落 `reconcile`/`deletion` receipt，`unresolved_retention`
  如实列出 provider 仍保留的条目，删除 receipt 保存
  `receipt_ref` + 原始 raw 报告。
- `handle_callback(job_id, callback_id, event, seq, artifacts,
  detail)` — savepoint + `export_callbacks` 幂等表（唯一约束
  `(workspace_id, job_id, callback_id)`）→ 重复回调
  `applied=False`；然后 `broker.handle_callback`（状态秩收敛）
  + `_apply_lineage` 写回 job。
- `import_returned_artifact(job_id, data, declared_digest, kind)`
  — `CAP_REVIEW_EXPORT`；非空 + ≤64MB + `sha256(data) ==
  declared_digest` 否则 `VALIDATION` 拒绝；Artifact 行
  `source_kind="derived"`、`classification="confidential"`、
  `review_state="quarantined"`、`rights.publishable=False`（绝不
  发布 model hub）→ Vault `begin_staging`/`append_bytes`/`commit`
  三段式落库，upload_state `receiving→committed`。本地校验不过
  的任何字节不进 vault。

### 3. 持久化 `persistence/models.py` + migration `0028_export_jobs`

- `ExportJob`：复合 FK `(workspace_id,payload_id)` →
  `export_transformed_payloads`、`(workspace_id,approval_id)` →
  `approvals`；唯一 `(workspace_id,id)`、
  `(workspace_id,payload_id,manifest_digest)`（同一 bound_digest
  内重试复用同一 job）；`status`（pending/transferring/
  transferred/running/succeeded/failed/cancelled/reconciling/
  deleted/denied）、`manifest_digest`、`payload_digest`、
  `recipient`/`permitted_job` JSONB、`expires_at`、
  `bytes_transferred`、`artifact_ids`、`seen_callback_ids`、
  `last_seq`、`exposed`(BigInteger，已出站字节数）、`external_state`、
  `last_error`。
- `ExportJobAttempt`：唯一 `(workspace_id,attempt_key)`；
  outcome ∈ validated/denied/transferred/failed/cancelled +
  reason + bytes_emitted。
- `ExportCallback`：唯一 `(workspace_id,job_id,callback_id)` —
  provider 回调幂等台账。
- `ExportReceipt`：kind ∈ reconcile/deletion/cancellation +
  receipt_ref + bytes + artifact_ids + unresolved_retention +
  exposed + raw 原始报告。

## Acceptance tests

- **AT-1003-1 [security]** payload/recipient/expiry 与批准不符 →
  **零出站字节**。覆盖层：服务层 `submit`（recipient/digest/job
  漂移 → `denied`）、`require_valid`（stale/expired/revoked →
  FORBIDDEN/STALE/EXPIRED）、gate 层（伪造 permit/payload 不符
  → EgressDenied 在 emit 前）、单次 permit 防重放、unknown
  provider → `failed` 如实记录。每个用例断言
  `double.received_bytes == 0`。
- **AT-1003-2 [security]** 执行中吊销 → `approvals.revoke` +
  `broker.revoke_binding` + live job cancel + reconcile；
  `ExportJob.exposed == 已出站字节数`，cancellation receipt 如实
  记录——**绝不声称未见**；后续 submit 在批准重校验处即被拒
  （零字节）。吊销仅限人类主体（agent `FORBIDDEN`）。
- **AT-1003-3 [integration]** callback 重复/乱序/交叉 →
  `export_callbacks` 幂等表去重 + 状态秩收敛 + 终态不回退 +
  artifact 并集 → 一致 job lineage；`seed_lineage` 从持久化行
  重启恢复。

## 已知限制

- 无真实云 provider — 生产 provider 一律 `not_configured`，全部
  路径经 in-process `ProviderDouble` 验证；capability 标签如实
  标注（非科学验证，仅 fixture）。
- 删除 receipt 依赖 provider 的诚实应答；无法核实的保留量在
  `unresolved_retention` 中如实列出，绝不臆造删除成功。
- 返回的 checkpoint/log 属于 confidential+untrusted derived data，
  digest 校验 + quarantine 后才入 vault；绝不发布至 model hub。
- `wall_seconds` permit 时长使用默认 3600s（manifest.limits 未带
  wall clock 字段）——实际 wall-clock 限额由 expiry + max_bytes +
  max_artifacts 约束；如需真实 wall-clock 计时由后续 lane 在
  provider 适配层落地。
- GraphQL/API 未接 broker — 本 lane 只交付域服务 + 持久化 +
  经纪层；resolver/UI 接线留给后续 ticket（CS-1004）。
