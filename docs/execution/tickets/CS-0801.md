## 实现内容

### 1. `packages/engine-adapters/sft/engine_adapter_sft/` — 钉版训练适配器

- `contracts.py`：纯 pydantic 契约，**无任何训练依赖 import**——核心
  服务不依赖 torch/peft。`SftTrainSpec`（`extra="forbid"`，模型/适配器/
  优化器/批/精度/检查点/资源包络/种子全量声明）、`SftTrainingExample`
  （context/messages/reviewed_response/partition/group_keys/rights——
  **无 hidden reasoning trace 字段**，`extra="forbid"` 拒绝夹带）、
  `SftCheckpoint`、`SftParameterProof`、`SftOutcome`、`SftResumeSpec`；
  `MODEL_LICENSES` 白名单（`fixture-internal` 允许训练；未知 license
  或 `training_allowed=False` 在契约层即拒）；`spec.digest()` /
  `example.digest()` 内容寻址。
- `pico.py`：`PicoGPT`（~0.86M 参数 GPT，`n_embd=64/n_head=4/n_layer=2/
  block=256`，种子确定性初始化——无下载、无预训练权重依赖）、
  `CharTokenizer`（sha256-digest 字符表）、`_Config`（满足 peft 的
  HF 式 config 探针）。诚实标注：fixture 基座，非科学模型。
- `trainer.py`：容器内训练循环——peft `LoraConfig` 注入
  `c_attn/c_proj`；AdamW + linear scheduler；fp32；NDJSON telemetry
  （`{event: step, step, loss, lr, wallSeconds, evalLoss?}`）；每
  `checkpoint.every_steps` 写 `ckpt-NNNNNN/`（adapter safetensors +
  optimizer.pt + meta.json{step, lineage}）；**resolved config 在首个
  update 前即持久化**（base/tokenizer hashes、adapter config、
  preprocessing、seeds、exact deps、optimizer、batch/accum、
  seq_length、precision、checkpoint policy、resource envelope 全量）；
  cancel → 收集现有 checkpoint 优雅退出；wall-clock 超时同样收获；
  resume → `_load_resume` 恢复 adapter+optimizer+step，lineage 追加
  resume provenance；`_relax()` 修复 safetensors 0600 写权限使
  宿主 harvester 可读。
- 参数证明 `SftParameterProof`：训练前/后 adapter sha256 + 冻结基座
  sha256 → `adapter_changed=True`、`frozen_changed=False`；reload →
  `reload_matches=True`。这是 AT-0801-1 的 REAL 证据。

### 2. `workers/training/sft/` — 隔离运行器（镜像 quantum/materials 模式）

- `Dockerfile`：`python:3.12-slim` 基座 + `requirements.lock` 冻结
  （torch 2.14.1+cpu pytorch-CPU index、peft 0.21.2、transformers
  5.18.0、accelerate 1.15.0——与 uv.lock 完全一致）；`HF_HUB_OFFLINE=1`
  `TRANSFORMERS_OFFLINE=1`；基座本地构造，运行时零下载。
- `runner.py`：读 `request.json{spec,dataset}` → `result.json` +
  `telemetry.ndjson` → stdout 仅 JSON；`EngineFailure`/`MemoryError` →
  `{code,message}` + exit 2；成功后 best-effort chmod 使产物宿主可读。
- `runtime.py`：`IsolatedSft` 经 `ContainerBackend`——`--network none`、
  只读根、UID 65534、cap-drop ALL、no-new-privileges、tmpfs /tmp；
  dataset/spec 经 tar 注入，resume checkpoint 经 `_pack_resume_tar`
  注入（**纯 basename 打包**，路径穿越成员被丢弃）；`_harvest`
  `PermissionError` 容忍；`ExecLimits{wall=cpu=wall_seconds, memory,
  pids, output}` 来自 spec 资源包络；cancel → `RUN_CANCELLED`（已
  harvest 的 checkpoint 保留）、超时 → `RUN_TIMEOUT`；`available()`
  = 镜像 `chem-studio-sft:0.1.0-v5` 存在。

### 3. `domain/learning/sft_examples.py` — §17.2–17.3 示例构建

- 来源：reviewed `ResearchSession` 消息（user/system/assistant/tool
  序列）、`EvidenceClaim`（supplier 链）、`Measurement`（带单位量）。
  每例记录 context、manifest、observable tool calls/results、reviewed
  response、label provenance、rights、split group——**绝不包含
  hidden reasoning trace**。
- 质量门在序列化**之前**运行并**逐项记录** `SftExclusion`：
  `hidden_reasoning_trace`（kind=rationale）、`unreviewed_response`
  （无 author principal）、`duplicate`（同 context+response）、
  `contradiction`（同 context 不同 response）、`missing_units`
  （claim 关联量缺单位）、`leaked_outcome_label`（held-out label
  出现在 body 且 partition≠final）。
- group-aware split 复用 CS-0602 `SplitPolicy`，group_keys 追加
  `dedup:<example_digest>` 保证同上下文不跨 split。

### 4. `domain/learning/sft.py` — 生命周期服务（§17.5，1016 行）

- `_ALLOWED` 状态机：`draft → dataset_validated → awaiting_approval →
  queued → running → completed → evaluating → candidate_release →
  rejected`（+ failed/cancelled/blocked）；**`promoted` 刻意缺席**——
  CS-0803 之前任何路径不可 promote；`completed` 仅表示产物存在。
- `create`：验证 snapshot（frozen、`assistant_sft` purpose）、
  `build_examples` 构建 dataset 并持久化（vault confidential）、
  spec 合并默认值 + `spec_digest` 落库 → `dataset_validated`。
- `submit` → `awaiting_approval`；`approve`：`approve_model` 能力
  （agents 永远没有）、`grant(action="training_run", bound_inputs=
  {snapshot_digest, spec_digest, dataset_digest})`——批准绑定到
  本次输入而非概念；rejected → `rejected`。
- `queue`/`execute` 两阶段跑 `_gate`（stage 标记）：**snapshot frozen
  + digest 比对 + manifest 重哈希 + drift 检测 + 实时 rights 重解析
  + license + `require_valid` 绑定批准 + dataset artifact checksum
  ——全部在 `vault.open_blob` 之前**（AT-0801-2：零字节读取即
  `blocked`，不读未授权训练字节）。
- `execute`：`accept_attempt`+`start_attempt`（执行 Run 归属清晰）→
  隔离训练 → `_persist_run_artifacts`（adapter/checkpoints/telemetry/
  resolved config → vault confidential，`SftCheckpoint.artifact` 记录
  目录名）→ `completed`/`failed`/`cancelled`；`admission.release`
  在所有终态路径释放预留。
- `cancel`：draft/dataset_validated/awaiting_approval → 直接
  `cancelled`；queued → `request_cancel`+`confirm_cancelled`+释放；
  running → `request_cancel`（容器优雅中断）。
- `resume`：`require_valid` 批准复查 + gate → 新 `RunAttempt`，
  `resumeFrom{fromStep, checkpoint{step,sha256}, sourceRunId,
  sourceAttemptId, resumedAt}` 写 provenance——输出可归因到 resume
  来源（AT-0801-3）。
- `transition`：`CAP_REVIEW_SCIENCE`，仅允许 completed→evaluating→
  candidate_release→rejected 的人工审阅流转；`promoted` 不可达。
- `capability` 标签：`scientificStatus=not_validated`、
  `dataStatus=fixture_only`、`engineCapability=live|not_installed`、
  `promotion=gated — CS-0803`、`egress=none`、
  `confidentiality=vault-scoped`。
