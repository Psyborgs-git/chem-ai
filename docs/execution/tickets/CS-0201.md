## Changed files

- `services/studio-api/src/studio/persistence/models.py` —
  `ResearchTask` gains `owner_id` (workspace-scoped principal FK),
  `target_kind` (`formulation|material|molecule|unknown` — unknown
  stays unknown), `mode_inputs` JSONB (kept verbatim), and
  `evaluation_cycle` (increments on reopen). New `TaskDecision`
  table records closure/reopen/review_return/state_change decisions

- `services/studio-api/migrations/versions/0005_task_lifecycle.py`
  — same shape in SQL plus `uq_decisions_scope_id` and
  `ix_task_decisions_task` keyset index.
- `services/studio-api/src/studio/domain/tasks/service.py` —
  `TaskService` centralizes the lifecycle: `create` (mode/scope
  validated; required-but-missing inputs persist as unresolved, never
  fabricated), `transition` (legal-state table §7.1, optional
  `expected_version` compare-and-swap, `awaiting_review→active`
  requires a review reason and records `review_return`), `close`
  (human-only + `review_science` + `awaiting_review` + closure
  decision from the allowed set; `supported_success` additionally
  passes the frozen-contract/required-metric evidence gate), `reopen`
  (closed-only, reason required, prior closure packet retained in the
  reopen decision, `evaluation_cycle += 1`), `draft_contract`
  (rev = max+1, draft status), `freeze_contract` (draft→frozen,
  prior frozen revision supersedes through the DB trigger's only
  legal transition, task's `current_contract_revision_id` repointed).
  Every command writes its outbox event + audit record in the
  caller's transaction.
- `services/studio-api/src/studio/domain/projects/service.py` —
  `ProjectService.get/create` (`edit_task` capability, outbox +
  audit in-transaction).
- `services/studio-api/src/studio/api/graphql/types.py` — `Task`
  gains `closureDecision`, `evaluationCycle`, `unresolvedInputs`,
  `targetKind`; new Relay nodes `ContractRevision` (revision, status,
  contentHash) and `Decision` (kind, payload, `decidedBy` via the
  request-scoped principal loader) — all resolved through the
  workspace-scoped `_by_ids`.
- `services/studio-api/src/studio/api/graphql/schema.py` —
  `taskDecisions(taskId:)` keyset connection; mutations
  `projectCreate`, `taskCreate` (now delegates to `TaskService`,
  accepting `targetKind`/`modeInputs`), `taskTransition`,
  `taskClose`, `taskReopen`, `contractDraftCreate`,
  `contractFreeze`. Every mutation supports `idempotencyKey` +
  `clientMutationId` and returns typed `errors` — `DomainError`s
  never escape as transport errors. `taskCreate` no longer
  hand-rolls the insert.
- `packages/contracts/schema.graphql` — re-exported (240 lines).
- `services/studio-api/tests/integration/test_task_lifecycle.py`
  — 11 integration tests.

## Acceptance mapping

- **AT-0201-1** (drafts in all three modes save/resume, keeping mode
  + unknown inputs — no fabricated thresholds):
  `test_all_three_modes_persist_with_unknowns` drives `taskCreate`
  for `improve`/`match_reference`/`discover` — mode persists,
  `targetKind` stays `"unknown"` when unset, `unresolvedInputs`
  reports exactly the missing mode-required fields
  (`baselineRevisionId`, `referenceProductId`, `targetKind`) and not
  the supplied ones (`variationScope`, `matchScope`).
  `test_mode_inputs_roundtrip_unmodified` proves the JSONB survives
  round-trip unmodified.
- **AT-0201-2** (closed task + changed success target → new contract
  accepted while original closure stays linked to its contract):
  `test_full_close_reopen_new_contract_keeps_link` — freeze rev A,
  close `supported_failure` (closure decision stores rev A), reopen
  (cycle 2, prior packet retained in the reopen decision), freeze
  rev B → task points at B, rev A supersedes via the trigger's only
  legal transition, and the closure decision still carries rev A's
  id.
- **AT-0201-3** (AI-proposed success cannot close; human review +
  evidence gates required): `test_agent_cannot_close` — an
  `agent`-kind principal gets `FORBIDDEN` even before capability
  checks, and a human researcher without `review_science` is denied.
  `test_supported_success_needs_frozen_contract_evidence` — reviewer
  closure of `supported_success` without a frozen contract →
  `EVIDENCE_INSUFFICIENT`; with a frozen contract requiring metrics
  → `EVIDENCE_INSUFFICIENT` listing the missing metric gates;
  only an empty-requirements frozen contract passes. Non-success
  closures (`inconclusive`, `stopped`, `supported_failure`) close
  normally for a reviewer — honest negative/inconclusive results
  don't need the evidence gate.

## Limitations

- The `supported_success` evidence gate checks for a frozen
  contract and non-empty `requiredMetrics`/`hardConstraints`; the
  "applicable reviewed measurements for every required metric" half
  waits on the measurement surfaces (P03/P04) — until then a
  contract that names metrics cannot clear the gate, and nothing is
  faked past it.
- `reviewer_id` is not yet assigned on `awaiting_review` entry —
  assignment policy lands with the review-workflow UI ticket.
- Task `update` (title/objective edit on a draft) is not yet a
  mutation; drafts save via `taskCreate` today. Session ownership
  (`owner_id` is recorded at create) is captured; resume-UI lands
  in CS-0206.
- `review_return` requires a reason but the reason's audience/
  routing is stored in the decision payload only — notifications
  are a later concern.
