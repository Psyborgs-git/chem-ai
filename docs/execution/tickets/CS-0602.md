## 实现内容

### 1. 分组与分区 `domain/learning/splits.py`（纯函数，无 I/O）

- `SplitRecord`：`record_id` + `group_keys`（`formula:<fam>`、
  `batch:<prep>`、`dedup:<hash>`、`doc:<group>`、`sample:<id>`）
  + `label` + `eligible`。
- `build_groups`：共享 key 的 union-find 连通分量 —— 公式兄弟、
  同批次、重复读数、派生文档永不跨分区（AT-0602-1）。
- `SplitPolicy`：fractions 含**强制性** `final` 分区
  （`final <= 0` → VALIDATION 拒绝）；种子化 group-id hash 决定
  分区指派，贪心填充欠配额分区 —— 确定性、与行序无关。
- `assign_partitions`：整个连通分量原子落区。

### 2. 污染检查 + 评估上下文清单

- `contamination_check`：held-out 记录出现在预测器训练谱系，或
  held-out id/label 值出现在评估上下文文本 → findings。
- `prepare_evaluation`：污染则 `EVAL_CONTAMINATION`（带
  safe_details.findings）；清洁则产出上下文 manifest ——
  分区计数、heldOutCount、heldOutIdsHash、predictorLineageHash、
  `scientificStatus: not_validated`（AT-0602-2）。

### 3. 分区限定拟合（AT-0602-3）

`fit_transform(records, features, assignment, transform,
allowed=("train",))`：`transform.fit` 仅收到 allowed 分区的行 —
测试/final 特征永不进 fit；`transform` 随后应用于全部记录。
`SplitTransform` Protocol 定义 fit/transform 契约。

### 4. 匹配基线 `workers/optimization/baselines/`

- `MeanBaseline`/`MedianBaseline`：fit/predict，仅见允许分区标签。
- `evaluate_baseline`：分母诚实报告（evaluated/missing/mae/
  smallSample）— 缺失标签计数而非静默丢弃（§18.2）。
- `denominator_report`（splits.py）：expected/reported/valid/
  missing/invalid/mean + 小样本不确定标注（n<30 →
  "treat as low-confidence; no accuracy claim"）。

### 5. `make eval-smoke` 落地 `tests/eval/smoke.py`

合成记录 → 分组 → 分区 → 分区限定 scaler → mean 基线 →
污染门控 manifest → 分母报告，端到端打印；仅 fixture。

## 已知限制 / 能力声明

- 分组 key 由调用方提供（`formula:`/`batch:`/`dedup:`/`doc:`/
  `sample:` 前缀约定）；从域记录自动推导 key 的接线属后续
  （数据集构建器 → split 的桥接）。
- 贪心分区为近似配额 —— 极小数据集上分区可能偏斜；
  `final` 非空仍被强制。
- 污染检查为 id/标签值文本匹配；更隐蔽的泄漏（改写表述、
  嵌入相似度）不在此层 —— §18.1 的模型谱系注册表属后续。
- 基线仅 mean/median；领域简单基线（如性质加和规则）在
  CS-0604 属性模型票中扩展。
- 全部合成 fixture；manifest 标注 `not_validated`。
